### 항목 1. 위험 놓침 방지율 (사례 단위, 0.85 이상)

| 단계 | 내용 |
|---|---|
| 쓰는 데이터 | 시험 22,740시간 가운데 위험 상태가 이어진 구간(위험사례) |
| 중간 결과 | `02_사례별_결과.csv` — 한 줄이 위험사례 1건. 사례ID · 시작·종료 시각 · 지속 시간 · 탐지(0/1) · 첫 탐지 시각 |
| 사례 만드는 법 | `02_시점별_결과.csv` 에서 `위험사례ID` 가 같은 줄을 한 사례로 묶는다 |
| 탐지 판정 | 그 사례의 줄 가운데 예측등급이 1 이상인 줄이 **한 번이라도** 있으면 탐지 = 1 |
| 최종값 | **놓침 방지율 = 탐지한 사례 수 ÷ 사례 수** (판정 항목 10개 각각) |
| 판정 | 10개 항목 각각 0.85 이상이면 적합 |
| 함께 내는 참고값 | 시간 단위 재현율 = (정답 1 이상이고 예측 1 이상인 줄 수) ÷ (정답 1 이상인 줄 수) |

**설명 문구**

> 첫 번째 항목, 위험 놓침 방지율입니다. 실제로 발생한 위험사례 가운데 AI 가 놓치지 않은 비율입니다.
>
> 위험사례는 위험 상태가 이어진 구간 하나를 말합니다. 시점별 결과 파일에 위험사례ID 열이 있습니다. 이 값이 같은 줄을 한 사례로 묶습니다. 그 사례에 속한 시각 가운데 한 번이라도 주의 이상으로 판단했으면 탐지한 것으로 셉니다.
>
> 예를 들어 이 줄들이 한 사례입니다. 예측등급 열에 1 이상이 있으므로 탐지입니다. 이렇게 사례마다 탐지 여부를 정한 것이 사례별 결과 파일이고, 탐지 열을 더해 사례 수로 나누면 놓침 방지율이 됩니다.
>
> `[항목명]` 은 사례 `[화면 값]` 건 가운데 `[화면 값]` 건을 탐지해 `[화면 값]` 입니다. 열 개 항목 가운데 `[화면 값]` 개가 0.85 이상입니다.
>
> 시간 단위 재현율은 위험 시각 하나하나를 맞혔는지 보는 값으로, 판정 기준이 아니라 참고값으로 같은 표에 싣습니다.

### 항목 2. 위험유형별 종합점수 (판정 조치단위 Macro F1, 0.80 이상)

| 단계 | 내용 |
|---|---|
| 쓰는 데이터 | 시험 22,740시간 전체(판정 항목마다 22,740줄) |
| 중간 결과 | `02_시점별_결과.csv` — 한 줄이 한 시각 × 판정 항목 1개. 정답등급 · 예측등급 · 정답_평가단위 · 예측_평가단위 · 일치 |
| 평가단위 | 주의와 경계의 조치가 다른 유형(고온·건조, 병해 유리환경)은 3등급 그대로. 조치가 같은 유형(강우·과습, 저온·서리, 복합위험)은 주의·경계를 「위험」으로 합쳐 2등급 |
| 혼동행렬 | 정답_평가단위 × 예측_평가단위의 줄 수를 센다 |
| 등급별 F1 | F1 = 2·TP ÷ (2·TP + FP + FN) |
| 최종값 | **Macro F1 = 등급별 F1 의 단순 평균** (3등급이면 3개, 2등급이면 2개의 평균) |
| 판정 | 10개 항목 각각 0.80 이상이면 적합 |

**설명 문구**

> 두 번째 항목, 종합점수입니다. 위험 등급 판정이 전체적으로 얼마나 맞는지를 Macro F1 으로 봅니다.
>
> 정확도를 쓰지 않는 이유는, 위험 시각이 전체의 몇 퍼센트뿐이라 전부 정상이라고 답해도 정확도가 90퍼센트를 넘기 때문입니다. Macro F1 은 드문 등급도 같은 비중으로 평균하므로 그런 문제가 없습니다.
>
> 시점별 결과 파일의 정답_평가단위 열과 예측_평가단위 열을 봅니다. 주의와 경계에서 농가가 하는 조치가 같은 유형은 둘을 위험 하나로 합쳐 정상 대 위험 두 등급으로 평가하고, 조치가 다른 유형은 세 등급 그대로 평가합니다.
>
> 이 두 열로 혼동행렬을 만듭니다. 등급마다 맞힌 수 TP, 잘못 부른 수 FP, 놓친 수 FN 을 세고, F1 을 2TP 나누기 2TP 더하기 FP 더하기 FN 으로 구합니다. 그 등급별 F1 을 단순 평균한 값이 종합점수입니다.
>
> 재계산 화면에 항목마다 혼동행렬과 등급별 F1 이 그대로 나옵니다. `[항목명]` 의 종합점수는 `[화면 값]` 이고, 열 개 가운데 `[화면 값]` 개가 0.80 이상, 가장 낮은 값이 `[화면 값]` 입니다.

| 단계 | 내용 |
|---|---|
| 쓰는 데이터 | 시험 445장의 모든 예측 상자와 정답 상자 3,699개 |
| 맞음(TP) 판정 | 예측 상자와 정답 상자의 겹침(IoU)이 0.5 이상이고, 그 정답이 아직 다른 예측에 쓰이지 않았으면 TP. 신뢰도가 높은 예측이 먼저 가져간다 |
| 중간 결과 | `02_예측별_결과.csv` — 전체순위(신뢰도 내림차순) · 신뢰도 · `TP@0.50` 열 |
| 계산 | 전체순위 순서로 TP·FP 를 누적 → 순위마다 정밀도 = 누적TP ÷ (누적TP + 누적FP), 재현율 = 누적TP ÷ 3,699 → 정밀도·재현율 곡선 |
| 최종값 | **AP = 곡선을 재현율 0~1 의 101점에서 보간해 평균한 값.** 클래스가 하나이므로 mAP@0.5 = AP |
| 판정 | 0.75 이상이면 적합 |
| 함께 내는 참고값 | 운영 임계값 0.25 에서의 정밀도 · 재현율 · F1, mAP@0.5:0.95 |

**설명 문구**

> 첫 번째 항목, 탐지 성능 mAP@0.5 입니다.
>
> 먼저 예측 상자 하나하나가 맞았는지를 정합니다. 예측 상자와 정답 상자가 겹친 넓이를 합친 넓이로 나눈 값이 0.5 이상이면 맞은 것으로 봅니다. 한 정답은 한 예측에만 짝지어지고, 신뢰도가 높은 예측이 먼저 가져갑니다.
>
> 예측별 결과 파일을 보시면 전체순위 열이 있습니다. 445장의 모든 예측을 신뢰도가 높은 순서로 한 줄로 세운 것입니다. 그 옆 TP 열이 맞았는지 여부입니다.
>
> 위에서부터 내려가며 맞은 수와 틀린 수를 누적하면, 순위마다 정밀도와 재현율이 나옵니다. 그 점들을 이은 곡선을 재현율 0부터 1까지 101개 지점에서 읽어 평균한 값이 AP 입니다. 클래스가 새우 하나이므로 이것이 곧 mAP 입니다.
>
> 한 가지 말씀드릴 점은, mAP 는 이미지별 값을 평균한 것이 아니라는 것입니다. 전체 예측을 한 줄로 세워 계산하는 값입니다.
>
> 오늘 측정값은 `[화면 값]` 으로 기준 0.75 이상입니다.

### 항목 2. 개체수 계수 오차율 (이미지별 평균 20% 이하)

| 단계 | 내용 |
|---|---|
| 쓰는 데이터 | 시험 445장 가운데 정답이 1마리 이상인 이미지 |
| 검출 수 | 그 이미지에서 신뢰도가 운영 임계값 0.25 이상인 예측 상자 수 |
| 중간 결과 | `02_이미지별_결과.csv` — 한 줄이 이미지 1장. 정답 수 · 검출 수 · 오차율 |
| 이미지별 오차율 | \|검출 수 − 정답 수\| ÷ 정답 수 |
| 최종값 | **이미지별 오차율의 평균** (중앙값 · 최대 · ±20% 안에 든 이미지 비율도 함께) |
| 판정 | 평균이 20% 이하이면 적합 |
| 따로 적는 것 | 정답 0마리 이미지는 나눌 수 없어 평균에서 빼고, 그 이미지들의 헛검출 수를 따로 적는다 |

**설명 문구**

> 두 번째 항목, 계수 오차율입니다. 현장에서 실제로 쓰는 값은 상자의 위치가 아니라 마릿수이므로, 마릿수가 얼마나 맞는지를 따로 봅니다.
>
> 이미지별 결과 파일의 한 줄이 이미지 한 장입니다. 정답 수와 검출 수가 있고, 둘의 차이를 정답 수로 나눈 값이 그 이미지의 오차율입니다. 예를 들어 정답이 10마리인데 9마리를 찾았으면 오차율은 10퍼센트입니다.
>
> 이 이미지별 오차율을 평균한 값이 최종값입니다. 오늘 `[화면 값]` 퍼센트로 기준 20퍼센트 이하입니다.
>
> 정답이 0마리인 이미지는 나눌 수 없어 평균에서 제외했습니다. 대신 빈 화면에서 잘못 찾은 수를 따로 적었습니다.

## ③ AI·데이터 — 수질 이상징후 탐지

### 공통: 학습 데이터와 시험 데이터

| 구분 | 내용 |
|---|---|
| 학습 데이터 | **없음.** 시험 대상은 학습 모델이 아니라 플랫폼의 판정 함수다 — 임계값 판정 `checkThresholds` 와 추세 판정 `detectTrendAnomalies` (`lib/thresholds.ts`) |
| 원본 자료 | 2024년 양식장 2곳, 수조 10개의 수기 수질일지. 항목은 수온 · pH · DO, 하루 2~4회 측정 |
| 시험 사례 | 한 수조의 약 7일 구간 시계열이 사례 1건. 모두 68건 — **이상 32건 · 정상 36건** |
| 정상 사례 | 실측 구간 그대로, 또는 기준에 못 미치는 작은 변화를 넣은 구간 |
| 이상 사례 | 실측 정상 구간에 라벨 기준표의 크기만큼 값을 주입해 만든 모사 사례. 주입한 항목·시각·크기를 사례 파일에 적었다 |
| 정답 기준 | 라벨 기준표 — 임계값 초과(DO 4.0 미만, pH 7.0 미만·8.5 초과), 급변, 연속 악화, 범위 이탈 |

**설명 문구**

> 이 건은 앞의 두 건과 다릅니다. 시험 대상이 학습한 모델이 아니라 플랫폼의 판정 함수이므로 학습 데이터가 없습니다. 수질 측정값이 기준을 벗어났는지 보는 임계값 판정과, 최근 흐름이 나빠지는지 보는 추세 판정, 두 함수가 시험 대상입니다.
>
> 시험 데이터는 2024년 양식장 두 곳, 수조 열 개의 수질일지에서 만들었습니다. 한 수조의 일주일치 기록이 사례 한 건이고, 모두 68건입니다. 이상 사례가 32건, 정상 사례가 36건입니다.
>
> 정상 사례는 실제 기록이거나, 기준에 못 미치는 작은 변화만 넣은 기록입니다. 이상 사례는 실제 정상 기록에 이상 값을 넣어 만든 모사 사례입니다. 실측 일지에는 기준을 벗어난 믿을 만한 기록이 없었기 때문입니다. 어느 항목에, 어느 시각에, 얼마만큼 넣었는지는 사례 파일에 건마다 적혀 있습니다.
>
> 정답은 라벨 기준표로 붙였습니다. 구간의 마지막 측정 시각에 관리자가 조치해야 하는 상태인지가 기준입니다.

### 항목 1. 수질 이상징후 탐지 정확도 (재현율 0.9 이상)

| 단계 | 내용 |
|---|---|
| 스크립트 | `eval-anomaly.mjs` → `recompute.mjs` |
| 시험 대상 확인 | `lib/thresholds.ts` 의 sha256 이 고정값과 같은지, 사례 파일 sha256 이 목록과 같은지 |
| 판정 | 사례마다 구간의 시계열을 판정 함수 두 개에 넣는다. 설정한 등급(주의·위험)의 결과가 하나라도 나오면 「이상」, 아니면 「정상」 |
| 중간 결과 | `02_사례별_결과.csv` — 한 줄이 사례 1건. 정답 · 판정 · 구분(TP·FN·FP·TN) · 출처(실측/모사) |
| 구분 | TP = 정답 이상·판정 이상 / FN = 정답 이상·판정 정상(놓침) / FP = 정답 정상·판정 이상(오경보) / TN = 정답 정상·판정 정상 |
| 최종값 | **재현율 = TP ÷ (TP + FN)** |
| 판정 | 0.9 이상이면 적합 |
| 함께 내는 참고값 | 정밀도 = TP ÷ (TP + FP) · F1 = 2TP ÷ (2TP + FP + FN) · 정확도 = (TP + TN) ÷ 전체 · 오경보율 = FP ÷ (FP + TN) |

**설명 문구**

> 시험 항목은 탐지 재현율입니다. 이상 사례 가운데 플랫폼이 이상으로 판정한 비율입니다.
>
> 먼저 판정 함수 파일이 기준 커밋의 것과 같은지, 사례 파일이 고정한 것과 같은지 해시로 확인합니다. 그다음 사례 68건을 하나씩 판정 함수에 넣습니다. 플랫폼이 실제 화면에서 쓰는 그 함수를 그대로 불러 씁니다.
>
> 결과 파일의 한 줄이 사례 한 건입니다. 정답 열과 판정 열이 있고, 그 옆 구분 열에 네 가지 가운데 하나가 적힙니다. 정답이 이상이고 판정도 이상이면 TP, 정답이 이상인데 판정이 정상이면 놓친 것이므로 FN 입니다. 정답이 정상인데 이상으로 판정했으면 오경보 FP, 둘 다 정상이면 TN 입니다.
>
> 재현율은 TP 를 TP 더하기 FN 으로 나눈 값입니다. 구분 열에서 TP 가 `[화면 값]` 건, FN 이 `[화면 값]` 건이므로 재현율은 `[화면 값]` 이고 기준 0.9 이상입니다.
>
> 정밀도와 오경보율 같은 값은 참고로 함께 싣습니다. 재계산 프로그램은 이 파일의 구분 열만 세어 같은 값이 나오는지 확인합니다.
