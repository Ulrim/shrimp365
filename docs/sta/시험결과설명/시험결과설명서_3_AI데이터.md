# 시험 결과 설명서 ③ — 쉬림프365 플랫폼 수질 이상징후 탐지 (V1.0)

주식회사 컬리버 · 시험일 2026-11-19 · 원격 입회시험(신청자 제시 기준 및 방법)

시험 항목 1개의 시험 과정과 결과값이 나온 경로를 정리한 문서입니다.

## 1. 시험 개요

| 항목 | 내용 |
|---|---|
| 시험 제품 | 양식 데이터 기반 흰다리새우 생산성 최적화 AI 플랫폼(쉬림프365) V1.0 |
| 기능 | 수조의 수질 측정값(수온·pH·DO)에서 이상징후를 판정해 알린다 |
| 시험 대상 | 플랫폼의 판정 함수 — 임계값 판정 `checkThresholds`, 추세 판정 `detectTrendAnomalies` (`lib/thresholds.ts`) |
| 판정 방식 | 기준값과 통계 규칙에 따른 판정. 가중치를 사전에 학습하는 방식이 아니다 |
| 시험 환경 | Windows 11 Home 64비트 · AMD Ryzen 7 7800X3D · RAM 32GB · GPU 사용 안 함 |
| 실행 방법 | `eval-anomaly.mjs`(측정) → `recompute.mjs`(재계산) |

| 시험 항목 | 기준 | 결과 | 판정 |
|---|---|---|---|
| 1. 수질 이상징후 탐지 정확도 (재현율) | 0.9 이상 | 0.9375 (93.75%) | 기준 충족 |

## 2. 판정 방식

| 판정 | 내용 |
|---|---|
| 임계값 판정 | 구간 마지막 시각의 측정값이 항목별 주의·위험 기준을 벗어났는지 비교한다 (예: DO 4.0 mg/L 미만이면 위험) |
| 급변 | 직전 측정과의 차이가 정해 둔 크기 이상인지 본다 |
| 연속 악화 | 일별 최고·최저값이 며칠에 걸쳐 한 방향으로 나빠지는지 본다 |
| 평소 범위 이탈 | 그 수조의 최근 기록으로 평균·표준편차를 계산해 크게 벗어났는지 본다. 판정할 때 그 구간의 기록으로 계산한다 |

두 함수 가운데 하나라도 주의 또는 위험 결과를 내면 「이상」, 아니면 「정상」으로 판정합니다.

## 3. 시험 데이터

| 항목 | 내용 |
|---|---|
| 원본 자료 | 2024년 양식장 2곳, 수조 10개의 수기 수질일지. 항목은 수온 · pH · DO, 하루 2~4회 측정 |
| 시험 사례 | 한 수조의 약 7일 구간 시계열이 사례 1건. **모두 68건** |
| 정상 사례 | **36건** — 실측 기록, 또는 기준에 못 미치는 작은 변화만 넣은 기록 |
| 이상 사례 | **32건** — 실측 정상 기록에 라벨 기준표의 크기만큼 값을 넣은 모사 사례 |
| 정답 기준 | 라벨 기준표. 구간의 마지막 측정 시각에 관리자가 조치해야 하는 상태인지로 정한다 |

실측 일지에는 기준을 벗어난 믿을 만한 기록이 없어 이상 사례는 모두 모사입니다. 주입한 항목·시각·크기는 사례 파일에 건마다 적혀 있습니다. 이 시험 결과는 모사 조건에서의 탐지 성능입니다.

본 판정 기능은 사전 학습을 하지 않으므로 학습 데이터가 없습니다. 원본 수질일지는 시험 사례의 바탕이 된 자료입니다.

| 이상 유형 (라벨 기준표) | 기준 |
|---|---|
| 임계값 초과 | DO 4.0 mg/L 미만, pH 7.0 미만 또는 8.5 초과 |
| 급변 | 수온이 직전 측정보다 4℃ 이상 변함, DO 가 2.5 mg/L 이상 하락 |
| 연속 악화 | DO 가 4일에 걸쳐 1.5 mg/L 이상 하락, 수온이 4일에 걸쳐 4℃ 이상 한 방향으로 변함 |
| 범위 이탈 | 마지막 두 측정이 그 수조의 직전 수준에서 DO 1.0 mg/L 이상 하락, 수온 1.5℃ 이상 상승, 또는 pH 0.3 이상 하락 |

## 5. 시험 항목 1 — 수질 이상징후 탐지 정확도 (재현율)

**시험 목적** — 이상 사례 가운데 플랫폼이 이상으로 판정한 비율을 측정한다.

**결과 도출 과정**

1. 사례마다 정답과 판정을 견줘 구분을 붙인다.

| 구분 | 정답 | 판정 | 뜻 |
|---|---|---|---|
| TP | 이상 | 이상 | 맞게 탐지 |
| FN | 이상 | 정상 | 놓침 |
| FP | 정상 | 이상 | 오경보 |
| TN | 정상 | 정상 | 맞게 정상 처리 |

2. 「구분」 열의 건수를 센다.

| 실제 \ 판정 | 이상 판정 | 정상 판정 | 합계 |
|---|---|---|---|
| 이상 | TP 30 | FN 2 | 32 |
| 정상 | FP 10 | TN 26 | 36 |
| 합계 | 40 | 28 | 68 |

3. 재현율을 계산한다.

```
재현율 = TP ÷ (TP + FN) = 30 ÷ (30 + 2) = 30 ÷ 32 = 0.9375
```

**결과** — 재현율 = **0.9375 (93.75%)** (기준 0.9 이상 충족)

**참고값** (판정 기준 아님)

| 값 | 산식 | 결과 |
|---|---|---|
| 정밀도 | TP ÷ (TP + FP) = 30 ÷ 40 | 0.7500 |
| F1 | 2·TP ÷ (2·TP + FP + FN) = 60 ÷ 72 | 0.8333 |
| 정확도 | (TP + TN) ÷ 전체 = 56 ÷ 68 | 0.8235 |
| 오경보율 | FP ÷ (FP + TN) = 10 ÷ 36 | 0.2778 |

정상 사례 36건 가운데 10건이 이상으로 판정되었습니다. 값은 소수 넷째 자리로 반올림해 표시하고, 기준 판정은 반올림 전 값으로 합니다.

## 6. 재계산 검증

`recompute.mjs` 는 `02_사례별_결과.csv` 의 「구분」 열만 세어 위 산식으로 최종값을 다시 계산하고 `03_최종결과.json` 과 비교합니다. 시험 시 모든 값이 일치했고 종료 코드는 0 이었습니다. 시험기관에서 TP 30건·FN 2건을 직접 세어 0.9375 를 확인했습니다.
