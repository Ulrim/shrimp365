## 1. 시험 대상·환경 확인 (신청서 절차 1)

```
node -v
git log -1 --format="%H %ad %s" --date=iso
git status --short lib/thresholds.ts raspberry-pi/anomaly.py
```

- 설명: 시험 대상은 `lib/thresholds.ts` 의 판정 함수이고, 위 커밋에서 바뀐 것이 없다(세 번째 명령 출력이 비어 있음).

## 2. 사례별 판정 실행 (신청서 절차 2·3)

```
node scripts/sta/eval-anomaly.mjs
```

- 화면에 나오는 것: ① 시험 대상 sha256 일치 ② 사례 파일 sha256 대조·건수 ③ 사례별 정답→판정 ④ 혼동행렬·재현율·정밀도·F1·정확도·오경보율·판정
- 생기는 것: `sta_AI데이터/` 의 `00_시험대상_해시.txt` `01_시험데이터/` `02_사례별_결과.csv` `03_최종결과.json` `05_실행로그.txt`
- 종료 코드: 0 적합 · 1 부적합 · 2 보류(기준값 미설정·사례 수 부족) · 3 실행 오류(해시 불일치 등)
- 엑셀로 `02_사례별_결과.csv` 를 열어 한 줄이 사례 한 건임을 보여 준다.

## 3. 재계산 (신청서 절차 4)

```

```

- `02_사례별_결과.csv` 만 읽어 최종값을 다시 계산하고 `03_최종결과.json` 과 비교한다. 모두 「일치」, 종료 코드 0.
- 생기는 것: `04_재계산_결과.txt` (같은 내용이 `05_실행로그.txt` 뒤에 붙는다)

## 4. 최종값 계산 과정 설명 (신청서 절차 5)

`02_사례별_결과.csv` 의 「구분」 열을 세면 된다.

| 구분 | 뜻 |
|---|---|
| TP | 정답 이상 · 판정 이상 |
| FN | 정답 이상 · 판정 정상 (놓침) |
| FP | 정답 정상 · 판정 이상 (오경보) |
| TN | 정답 정상 · 판정 정상 |

- **재현율(판정 기준) = TP ÷ (TP + FN)** — 이상 사례 가운데 플랫폼이 이상으로 판정한 비율
- 정밀도 = TP ÷ (TP + FP) · F1 = 2TP ÷ (2TP + FP + FN) · 정확도 = (TP + TN) ÷ 전체 · 오경보율 = FP ÷ (FP + TN)
- 값은 소수 넷째 자리 반올림. 기준 판정은 반올림 전 값으로 한다.
- 「출처」 열(실측/모사)로 걸러 같은 셈을 하면 출처별 값이 나온다.
- 판정은 사례 구간을 플랫폼 함수 `checkThresholds`(마지막 시각의 측정값) + `detectTrendAnomalies`(구간 시계열)에 넣어 얻는다.
  하나라도 설정한 등급(`이상으로_세는_등급`)의 결과가 나오면 「이상」.
- 참고 열: 「대상 항목 탐지」(라벨의 대상 항목까지 맞췄는가), 「웹-장비 추세 일치」(장비 `anomaly.py` 와 같은 추세 판정인가). 판정 기준에는 쓰지 않는다.

## 문제가 생기면

| 증상 | 조치 |
|---|---|
| `이 Node(...)는 .ts 파일을 바로 실행하지 못합니다` | Node 22.18 이상으로 올린다 |
| `시험 대상 파일이 고정한 해시와 다릅니다` | 줄바꿈 변환을 의심한다 — `git config core.autocrlf false` 후 다시 clone. 코드를 고친 것이 아니면 시험 대상 커밋을 다시 받는다 |
| `sha256 불일치: series/...` | 사례 파일이 바뀌었다. 전날 확정한 묶음으로 되돌린다 |
| `보류(기준값 미설정)` | `sta.config.json` 의 `기준_재현율` 을 채운다 |
