### 4-3. 건별 실행과 설명 요지

**① AI 노지** — 꾸러미에서 `4_test` (끝에 「전 단계 통과」)

- 하는 일: 판단 코드·모델 56개 해시 확인 → 저장된 모델로 시험셋 판정(학습 없음) → 재계산 → 판단시간 200회 → zip
- 종합점수: 항목마다 정답·예측 평가단위로 혼동행렬을 만들고 등급별 F1 의 단순 평균이 Macro F1
- 놓침 방지율: `위험사례ID` 가 같은 줄을 한 사례로 묶어, 한 번이라도 위험으로 판단했으면 탐지. 탐지 사례 수 ÷ 사례 수
- 판단시간: 판단 1회(피처 생성 → 추론 → 판단근거 → 조치 결정 → 이력 기록)를 200회 재어 평균이 30초 이내인지
- 시간 단위 재현율(참고)과 위험사례 30건 미만 항목은 결과에 그대로 표시된다 — 빼거나 합치지 않는다

**② 블루스타트업** — 꾸러미에서 `4_시험당일.bat`

- 하는 일: git 커밋·모델 sha256 → 445장·3,699개 확인 → 시험 데이터 sha256 대조 → 측정 → 재계산
- mAP@0.5: 모든 이미지의 예측을 `전체순위`(신뢰도 내림차순)로 세우고 `TP@0.50` 열로 누적 TP·FP → 정밀도·재현율 곡선 → 101점 보간 평균. **이미지별 AP 의 평균이 아니다**
- Precision·Recall·F1: TP = 정답별 로그의 「운영임계값에서_탐지」=1 줄 수, FP = 예측별 로그의 「운영임계값_이상」=1 줄 수 − TP, FN = 정답 수 − TP
- 계수 오차율: 이미지마다 |검출 수 − 정답 수| ÷ 정답 수의 평균. 정답 0마리 이미지는 제외하고 헛검출 수를 따로 적는다

**③ AI·데이터** — 저장소에서 명령 세 묶음

```
node -v
git log -1 --format="%H %ad %s" --date=iso
git status --short lib/thresholds.ts raspberry-pi/anomaly.py
node scripts/sta/eval-anomaly.mjs
node scripts/sta/recompute.mjs
```

- 시험 대상은 플랫폼 판정 함수(`lib/thresholds.ts` 의 `checkThresholds` · `detectTrendAnomalies`)이고 기준 커밋에서 바뀌지 않았다
- `02_사례별_결과.csv` 의 「구분」 열(TP·FN·FP·TN)을 세면 된다. **재현율 = TP ÷ (TP + FN)**
- 정밀도·F1·정확도·오경보율은 함께 내는 참고값. 종료 코드 0 적합 · 1 부적합 · 2 보류 · 3 실행 오류

## 8. 아직 정해야 하거나 확인할 것

| 건 | 내용 | 영향 |
|---|---|---|
| ① | 놓침 방지율을 **사례 단위**(A안)로 판정할지 **시간 단위**(B안)로 할지. 정정안은 A안 기준. 시간 단위로 읽히면 10개 중 4개 항목이 0.85 에 못 미친다 | 신청서 문구와 판정 결과 |
| ① | 「항목별 데이터 30건 이상」이 시점 표본 기준인지 위험사례 기준인지 STA 에 확인. 사례 기준이면 강우·과습 21건, 복합위험 18건으로 모자란다(정정안 3절에 문의 메일 초안) | 두 유형의 판정 방식 |
| ① | 신청서의 시험 표본 수(20,063시간)를 예행연습 실제 값으로 고친다 | 신청서 기재값 |
| ② | 시험 당일 쓸 꾸러미를 수정판으로 통일하고 사전 측정을 다시 한다 | 참고값(탐지율 하한) |
| ② | 신청서 붙임의 캡처는 이전 판 화면이다(탐지율 하한 0.9200) | 붙임과 당일 값이 다르게 보임 |
| ③ | `sta.config.json` 의 【결정 필요】 두 항목 — 「이상으로 세는 등급」(주의·위험 / 위험만), 「판정 방식」(구간끝 / 순차) | 재현율 값 |
| ③ | 사례 묶음이 이상·정상 각 30건 이상인지 | 30건 미만이면 종료 코드 2(보류) |
| 공통 | 세 건을 같은 시험 PC에서 하는지, 건별 신청서의 「시험환경」이 그 PC 사양과 같은지 | 신청서 기재값 |

> ①·③의 예행연습 결과는 이 문서를 쓰는 시점에 확인하지 못했다. ②는 시험 PC 사전 측정 결과를 받아 확인했다.
