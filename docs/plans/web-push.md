# 웹푸시 — 앱을 닫아도 오는 위험 알림

## 왜 만들었나

기존 기기 알림은 브라우저 탭 안에서 `new Notification()` 으로 띄우는 인탭 방식이었다.
문제가 두 가지였다.

1. **탭이 살아 있어야만 뜬다.** 새벽 세 시에 DO 가 무너지는 순간이 정확히 이 알림이
   필요한 때인데, 그때 앱은 닫혀 있다.
2. **안드로이드 크롬은 그 생성자를 아예 막는다.** 서비스워커의 `showNotification` 을
   요구한다. 양식장 운영자 주력 단말이 그쪽이라 실제로 한 건도 안 왔다.

서비스워커 + 서버 푸시(웹푸시 + VAPID)로 둘 다 해결한다.

## 동작

```
센서가 값을 올림 (POST /api/sensors/data)
  └ 임계값 초과 판정
      ├ 새 알림 insert          → sendAlertPush()
      └ 기존 알림 주의 → 위험    → sendAlertPush()   (등급이 그대로면 보내지 않음)
            └ tanks → farms.user_id 로 수조 주인을 찾음
                └ push_subscriptions 에서 그 사용자의 모든 기기 조회
                    └ web-push 로 발송 (410/404 이면 그 구독을 DB 에서 삭제)
                        └ 기기의 public/sw.js 가 받아 OS 알림으로 표시
```

- **VAPID 환경변수가 하나라도 없으면 아무것도 하지 않는다.** 센서 수집은 그대로
  동작하고, 화면 알림은 기존 인탭 방식으로 폴백한다. 키를 넣기 전에 배포해도 안전하다.
- 발송 실패는 전부 `sendAlertPush` 안에서 삼킨다(`console.error` 로만 남는다).
  **푸시 때문에 수질 데이터가 유실되는 일은 없다.**
- 브라우저에 푸시 구독이 살아 있으면 클라이언트는 인탭 알림을 띄우지 않는다.
  서버가 이미 보냈으므로 그러지 않으면 같은 알림이 두 번 뜬다.

## 사람이 해야 할 일

에이전트는 코드와 SQL 파일까지만 만든다. 아래 다섯 가지는 사람이 직접 해야 한다.

### ① VAPID 키 생성 (한 번만)

```bash
npx web-push generate-vapid-keys
```

`Public Key` 와 `Private Key` 가 나온다. **한 번 만들어 두고 계속 쓴다.**
키를 바꾸면 이미 구독한 기기가 전부 무효가 되어, 농가가 알림을 다시 켜야 한다.

### ② Vercel 환경변수 3개 등록

Vercel → 프로젝트 → Settings → Environment Variables (Production/Preview 모두)

| 이름 | 값 |
|---|---|
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | ①의 Public Key |
| `VAPID_PRIVATE_KEY` | ①의 Private Key — **서버 전용, 절대 `NEXT_PUBLIC_` 로 두지 말 것** |
| `VAPID_SUBJECT` | `mailto:contact@culiver.ai` |

`NEXT_PUBLIC_VAPID_PUBLIC_KEY` 는 빌드 시점에 클라이언트 번들에 박힌다.
**등록한 뒤 반드시 재배포해야** 브라우저가 구독할 수 있다.

셀프호스팅(NAS·도커)이면 같은 3개를 `.env` 에 넣고 컨테이너를 재시작한다.

### ③ Supabase 마이그레이션 실행

Supabase Dashboard → SQL Editor 에서 다음 파일 내용을 붙여넣고 실행한다.

```
supabase/migrations/push_subscriptions.sql
```

(통합본 `supabase/migrations/_ALL_required.sql` 에도 포함되어 있다. 재실행 안전.)

만드는 것: `push_subscriptions` 테이블, `user_id` 인덱스, RLS 정책 4개,
`save_push_subscription()` 함수.

> 실행하지 않으면 `/api/push/subscribe` 가 500 을 돌려주고, 화면은 조용히
> 인탭 알림으로 폴백한다. 앱이 깨지지는 않지만 푸시는 안 온다.

### ④ 브라우저에서 알림 켜기

앱 → 우상단 종 아이콘 → **기기 알림 켜기** → 브라우저 권한 창에서 허용.

성공하면 확인 알림이 한 번 뜨고, 패널 문구가
**"기기 알림 켜짐 — 앱을 닫아도 받습니다"** 로 바뀐다.
이 문구가 아니라 그냥 "기기 알림 켜짐" 이면 푸시가 아니라 인탭 방식으로 폴백한
상태다(②나 ③이 빠졌거나 브라우저가 푸시를 지원하지 않음).

기기마다 한 번씩 켜야 한다. 구독은 브라우저·기기 단위다.

### ⑤ iOS 는 홈 화면 추가가 필수

iOS 사파리는 **홈 화면에 추가된 PWA 안에서만** 웹푸시를 허용한다.
그냥 사파리 탭에서는 알림 켜기 버튼을 눌러도 구독이 되지 않는다.

아이폰: 사파리로 접속 → 공유 버튼 → **홈 화면에 추가** → 홈 화면 아이콘으로
앱을 연 뒤 ④를 진행.

(iOS 16.4 이상. PWA 매니페스트는 `app/manifest.ts` 로 이미 있고 Next 가
`<link rel="manifest">` 를 자동으로 넣어 준다 — `display: "standalone"`,
192·512 아이콘까지 이미 갖춰져 있어 이번 작업에서 손댈 것이 없었다.)

## 확인 방법

- 알림 패널 문구가 "앱을 닫아도 받습니다" 인지.
- Supabase → Table Editor → `push_subscriptions` 에 줄이 생겼는지.
- 실제 알림: 수조 임계값을 잠깐 좁히거나 테스트 장비로 범위 밖 값을 한 번 올려
  **새 알림이 생기게** 한다. 이미 열려 있는 같은 항목 알림은 등급이 오를 때만
  푸시가 나간다(1분마다 같은 푸시가 쌓이지 않게 한 의도적 설계).

## 알아 둘 것

- **구독은 만료된다.** 브라우저가 오래된 구독을 버리거나 앱을 오래 안 열면 끊긴다.
  서버는 410/404 를 받으면 그 구독을 지우고, 클라이언트는 앱을 열 때마다 권한이
  이미 허용돼 있으면 조용히 다시 구독한다(권한 창은 뜨지 않는다).
- **`public/sw.js` 에 fetch 핸들러를 넣지 말 것.** 캐싱을 붙이는 순간 앱의 모든
  네트워크 요청이 그 워커를 거치게 되고, 로그인 세션·수질 데이터까지 오래된
  사본이 나갈 수 있다. 이 서비스워커는 오직 푸시용이다.
- 푸시 페이로드에는 수조 이름과 알림 문구가 들어간다. 잠금화면에 그대로 뜨므로
  민감한 값을 더 넣지 말 것.
