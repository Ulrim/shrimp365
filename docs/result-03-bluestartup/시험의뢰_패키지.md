## 1. 시험 항목과 지표 정의

| | 항목 | 기준 | 측정 수단 | 상태 |
|---|---|---|---|---|
| ① | 새우 객체탐지 모델 성능 | mAP@0.5 **0.75 이상** (P·R·F1 동시 산출) | `vision/ai/trainer/eval_detect.py` | 1차 측정 완료(valid 15장) · **test 445장 남음** |
| ② | 개체수 계수 오차율 | 시험기관 협의 (사내 기준 ±20%) | 같은 실행에서 함께 나옴 | 1차 측정 완료 · **밀집 조건 미검증**(§6-2) |
| ③ | 엣지 장치 추론 처리시간 | 시험기관 협의 (사내 기준 3초 이내) | `vision/ai/trainer/export_edge.py --bench` | 수단 준비됨 |

세 항목 모두 **배포본과 같은 코드 경로**(`vision/app/services/detector_onnx.py`)로
추론한다. 전처리(letterbox)·NMS·좌표 복원이 현장 장비에서 도는 것과 같은 코드다.
"시험용으로 따로 만든 경로"의 성적이 아니다.

### ① 탐지 성능 — 지표 정의

* **IoU** — 두 박스가 겹친 넓이 ÷ 합친 넓이.
* **TP** — 정답 박스와 IoU 가 기준 이상이고, 그 정답이 아직 다른 예측에 쓰이지
  않은 예측. 한 정답은 한 예측에만 대응하며 신뢰도가 높은 예측이 먼저 가져간다.
* **FP** — TP 가 되지 못한 예측. **FN** — 어느 예측도 가져가지 않은 정답.
* **Precision** = TP / (TP + FP) — 예측한 것 중 맞은 비율
* **Recall** = TP / (TP + FN) — 실제 있는 것 중 찾은 비율
* **F1** = 2PR / (P + R)
* **AP** — 신뢰도 내림차순으로 PR 곡선을 그려 **101점 보간**으로 적분(COCO 방식).
* **mAP@0.5** — IoU 0.5 기준 AP. 클래스가 하나(`shrimp`)이므로 AP 와 같다.
* **mAP@0.5:0.95** — IoU 0.50~0.95 를 0.05 간격으로 10번 잰 AP 의 평균.

P·R·F1 은 **운영 신뢰도 임계값**에서 잰다(기본 0.25, `--conf`). mAP 는 임계값과
무관한 곡선 전체의 값이므로 내부적으로 0.001 까지 낮춰 추론한다(`--map-conf`).

### ② 계수 오차율 — 지표 정의

```
한 장의 오차율 = |예측 마리 수 − 실제 마리 수| ÷ 실제 마리 수
```

이것을 이미지별로 내고 **평균·중앙값·최대**와 **±20% 안에 든 장면의 비율**을
보고한다. 탐지 지표가 "박스가 제자리에 있나"를 보는 것과 달리, 현장에서 쓰는
값은 마리 수다. 박스가 조금 어긋나도 수가 맞으면 쓸 수 있고, 박스가 정확해도
몇 마리를 빠뜨리면 못 쓴다. 그래서 따로 센다.

정답이 0마리인 배경 이미지는 분모가 0이라 오차율을 낼 수 없다. **빼지 않고 따로
센다** — 빈 수조에서 헛검출이 몇 개 나오는지가 중요하기 때문이다.

### ③ 엣지 추론 처리시간 — 측정 조건

* 장비: 라즈베리파이 4 Model B (4GB), Raspberry Pi OS Bookworm 64-bit
* 런타임: onnxruntime (torch 없음), 스레드 수는 `INFERENCE_THREADS` 설정값
* 재는 구간: **한 프레임의 전처리 + 추론 + 후처리 전체.** 카메라 캡처와 업로드는
  제외한다.
* 보고값: 중앙값과 p95. **첫 회는 모델 적재가 섞이므로 따로 적고 통계에서 뺀다.**
* 입력 프레임은 실제 수조 사진을 쓴다(`--image`). 합성 프레임은 검출이 거의 없어
  후처리 비용이 실제보다 싸게 나온다.

## 3. 시험 데이터 인계

### 무엇을 보내는가

학습에 **쓰지 않은** test 분할이다. 학습 기록(`docs/VISION_MODEL_TRAINING.md` §8)
기준으로 **445장 / 정답 개체 3,699개**다.

```
test/
  images/   445장  (.jpg)
  labels/   445개  (.txt, 이미지와 같은 파일명)
  sha256sums.txt
  통계.txt   장수·개체수·마리수 분포
```

### 왜 이 분할을 믿을 수 있는가

`vision/ai/trainer/prepare_dataset.py` 가 나눈다. 두 가지를 보장한다.

1. **씨앗 고정**(`seed=20260101`) — 같은 입력에 같은 분할이 나온다. 다시 돌려도
   같은 445장이다.
2. **증강 사본 누수 차단** — shrimp_cf 는 증강한 뒤에 분할했기 때문에, 같은 원본
   프레임의 사본이 train 과 test 에 흩어져 있었다. 그대로 쓰면 "학습에 쓴 사진을
   변형한 것"으로 시험하게 된다. 스크립트가 같은 원본에서 나온 사본들을 한 분할에
   몰아넣어 이것을 없앤다(학습 당시 누수 0건).

### 라벨 형식

한 줄에 한 객체, 좌표는 0~1 정규화. 두 가지를 모두 받는다.

```
0 cx cy w h                      박스
0 x1 y1 x2 y2 x3 y3 …            폴리곤(점 3개 이상) → 외접 박스로 접는다
```

shrimp_cf 원본은 폴리곤(25점·16점 등)이다. **변환하지 않고 그대로 넣으면 된다.**
`eval_detect.py` 가 외접 박스로 접는다. 시험기관에는 폴리곤 그대로 보내도 되고,
시험기관이 박스를 원하면 접힌 값을 같이 보낸다.

### 만드는 명령 (우리 쪽)

```bash
cd vision
python ai/trainer/prepare_dataset.py \
  --source shrimp_cf='<드라이브>/01. 흰다리새우 학습 데이터/03. shrimp_cf/shrimp_cf.v1i.yolov8' \
  --source counting_pl='<드라이브>/01. 흰다리새우 학습 데이터/04. Counting PL/Counting PL.v1i.yolov8' \
  --out datasets/shrimp

cd datasets/shrimp/test && sha256sum images/* labels/* > sha256sums.txt
```

## 6. 남은 위험 둘

### (1) 배포본의 mAP 가 측정된 적이 없다 — 가장 큰 위험

`docs/VISION_MODEL_TRAINING.md` §8 의 **mAP@0.5 0.924 는 `.pt` 가중치를 640px 로
잰 값**이다. 시험 대상은 **416px ONNX** 다. 해상도를 640에서 416으로 내리고 ONNX
로 내보내면 작은 개체의 탐지가 떨어지므로, 416 ONNX 의 mAP 는 0.924 보다 낮다.
**얼마나 낮은지는 아무도 모른다.** 0.75 를 넘는지도 모른다.

계수 오차율 쪽은 416 ONNX 로 잰 값이 있다(밀집 valid 185장 5.0%). 탐지 지표만
빈 칸이다.

대비책, 가능성이 높은 순서로:

1. **선행 측정**(부록 B). 결과가 0.75 이상이면 그대로 의뢰한다.
2. 0.75 에 못 미치면 **`--conf` 조정은 답이 아니다** — mAP 는 임계값과 무관하다.
   대신 **640px ONNX 를 다시 내보내 재측정**한다(`export_edge.py`). 파이의 처리
   시간이 늘어나므로 ③과 맞바꾸는 셈이고, 어느 쪽을 보고할지 결정이 필요하다.
3. 그래도 안 되면 **기준을 협의**한다 — mAP@0.5 0.75 는 우리가 제시한 값이다.
   P·R·F1 과 계수 오차율로 성능을 말하고 mAP 는 참고로 두는 구성이 가능한지
   접수 때 묻는다.

### (2) 현장 데이터로 잰 값이 아니다

test 445장은 공개 데이터셋(shrimp_cf + Counting PL)의 분할이다. 우리 수조는 물
색·조명·각도가 다르다. 성적서에는 "제공된 시험 이미지에 대한 성능"으로 적히고,
실제 수조 정확도는 **카메라를 현장에 고정한 뒤에야** 잴 수 있다. 결과보고서에
이 구분을 분명히 적어야 한다.

## 부록 B. test 445장 측정 — 명령 하나

성적서에 올릴 수치는 **test 445장**으로 받는다. 그 445장은 원본 데이터셋 **전체**를
`prepare_dataset.py` 가 다시 섞어 만드는 것이라, 일부만으로는 재현할 수 없다.

### B-1. 준비

원본 Roboflow 내보내기 두 벌이 필요하다(둘 다 `data.yaml` 과 `train/valid/test` 가
들어 있는, 압축을 푼 폴더).

| 데이터셋 | 어디서 |
|---|---|
| `shrimp_cf` 5,032장 | 드라이브, 또는 [Roboflow Universe](https://universe.roboflow.com/ktteam/shrimp_cf-qffxh) (CC BY 4.0) |
| `Counting PL` 213장 | 드라이브 |

```bash
cd vision
pip install -e ".[edge]"      # numpy·onnxruntime·pillow·pydantic
```

### B-2. 실행

```bash
# (가) 두 폴더를 이미 가지고 있을 때 — 가장 확실하다
./ai/trainer/run_test_eval.sh <shrimp_cf 폴더> <Counting PL 폴더>

# (나) shrimp_cf 를 Roboflow 에서 바로 받을 때
export ROBOFLOW_API_KEY='...'          # Roboflow → Account → Roboflow Keys
./ai/trainer/run_test_eval.sh --from-roboflow <Counting PL 폴더>
```

키는 **명령줄에 적지 않는다** — 셸 기록에 남는다. 환경변수로만 준다.

스크립트가 하는 일은 셋이다.

1. 두 데이터셋을 합치고 **학습 때와 같은 방식으로 다시 나눈다**
   (`--on-leakage regroup`, 씨앗 20260101 → train 3,927 / valid 873 / test 445).
   증강 사본이 학습 분할과 섞이지 않도록 원본 프레임 단위로 묶어 옮긴다.
2. 그 test 445장으로 배포본(416 ONNX)의 mAP·P·R·F1·계수 오차율을 잰다.
   추론은 현장 장비와 같은 코드 경로(`app/services/detector_onnx.py`)로 한다.
3. 결과를 `docs/result-03-bluestartup/evidence/08_탐지성능_test분할.{json,csv}` 에
   떨어뜨린다.

test 가 445장이 아니면 경고한다. 그때는 원본 데이터셋이 학습 당시와 다른 것이므로,
"학습에 쓰지 않은 이미지"라는 설명이 어긋난다 — 멈추고 원본을 확인한다.

### B-3. 끝난 뒤

* 출력 JSON·CSV 를 **커밋한다.** 그래야 결과보고서의 수치가 "문서 기재값"이 아니라
  "재현 가능한 측정값"이 된다. JSON 에는 측정 당시 읽은 모델의 sha256 이 함께 박힌다.
* ③ 엣지 처리시간은 **라즈베리파이에서** 따로 잰다.

  ```bash
  python ai/trainer/export_edge.py --bench --runs 30 \
    --weights ai/models/shrimp_yolov8n_416.onnx --image <실제 수조 사진>.jpg
  ```

* 판단 기준은 하나다 — **`mAP@0.5` 가 0.75 이상인가.** 넘으면 의뢰하고, 못 넘으면
  §6 (1) 의 2번으로 간다.

### B-4. 이미 알고 있는 것 (2026-11-11 1차 측정)

드라이브에서 받을 수 있었던 **valid 15장·정답 18개**로 배포본을 먼저 재 봤다.

| 항목 | 값 |
|---|---|
| mAP@0.5 | 1.0000 |
| Precision / Recall / F1 | 1.0000 / 1.0000 / 1.0000 |
| 계수 오차율 | 평균 0.0%, ±20% 이내 100% |
| 탐지율 95% 하한 | **0.8147** |

증빙: `evidence/07_탐지성능_1차측정.json`. 18개를 모두 맞혔지만 "100%"라고 쓸 수는
없다 — 18개로 말할 수 있는 최대치가 하한 0.8147 이고, 그것도 기준 0.75 를 넘는다.

**다만 이 표본은 우리 수조 조건이 아니다.** shrimp_cf 는 쟁반·얼음·흰 배경 위의
새우 사진이고 한 장에 1~3마리다. 계수 오차 0% 는 "한 마리를 한 마리로 셌다"는
뜻이지 밀집 수조 계수를 검증한 것이 아니다. 445장으로 다시 재도 이 성격은 같다 —
보고서에는 §6 (2) 의 구분을 반드시 함께 적는다.
