# 03 블루스타트업 — 결과보고서 자료집

**과제** 수중 카메라 AI 를 이용한 양식 개체수·성장 계측 (종료 2026. 11. 30.)
**정리일** 2026. 10. 21.
**대상 저장소** `ulrim/shrimp365` — 비전 서비스 `vision/`, 웹 `/vision`, 배포 `public/updates/vision/`

결과보고서를 **쓸 때 바로 꺼내 쓰도록** 그림과 시험 결과를 모아 둔 폴더다.
세 가지 원칙으로 만들었다.

1. **그림은 실제 화면에서 뜬다.** 시안을 그려 넣지 않는다 — 그리는 순간 실물과 어긋나고,
   점검위원이 화면을 열어 보면 다른 그림이 나온다.
2. **숫자는 실행 기록에서 나온다.** 사람이 옮겨 적은 "통과했습니다"는 증빙이 아니다.
   각 결과 파일 머리에 언제·어느 커밋에서·무슨 명령으로 돌렸는지가 적혀 있다.
3. **없는 것은 없다고 쓴다.** 아래 「아직 증빙이 안 되는 것」이 그 목록이다.
   보고서에 그 항목을 쓰려면 먼저 그 일을 해야 한다.

> 보고서에 실을 수 없고(타 농장 자료), 서비스 롤 키를 이 저장소에 둘 수도 없다.

### 시험 중 발견해 고친 것 (보고서에 쓸 수 있는 품질 활동)

- **시험 1건이 간헐적으로 실패**했다(12회 중 1회). 원인은 코드 결함이 아니라 시험 방식이었다 —
  고정된 1초 대기 후 결과를 보는 구조라, 기계가 바쁜 첫 실행에서는 멀쩡한 코드가 떨어졌다.
  **시간을 재는 대신 결과가 나올 때까지 기다리도록** 고쳤다(`vision/tests/test_cameras.py`).
  재현되지 않는 시험은 증빙이 되지 못한다.
- **화면 점검이 사진 없이 통과하고 있었다.** 시험용 사진을 환경변수로만 받아, 그 값을 넘기지
  않으면 빈 이미지로 점검이 돌았다. 장비와 같은 코드로 생성한 사진을 파일로 고정했다
  (`scripts/fixtures/`).

## 4. 아직 증빙이 안 되는 것 — 보고서에 쓰기 전에 읽을 것

이 네 가지는 **코드로 해결되지 않는다.** 숨기면 점검에서 더 크게 문제가 된다.

### ① 모델 성능 수치를 재계산할 수 없다

`docs/VISION_MODEL_TRAINING.md` 에 mAP@0.5 **0.924**, 계수 오차 **2.2%**(test 445장),
±20% 이내 **98.9%** 가 적혀 있으나, **학습·평가 데이터셋과 평가 출력 파일이 저장소에 없다.**
따라서 지금은 그 숫자를 다시 계산해 확인할 방법이 없고, 이 자료집도 그 숫자를 싣지 않았다.

- 해야 할 일: 평가 데이터셋을 확보해 `vision/ai/trainer/eval_count.py` 를 다시 돌리고,
  **출력 JSON·CSV 를 이 폴더에 커밋**한다. 그러면 숫자가 서술이 아니라 자료가 된다.
- 추가로 **보고서에 어느 모델을 쓸지 먼저 정해야 한다.** 과거 보고된 0.7642 모델의 가중치는
  저장소 어디에도 없고, 현재 배포본은 2026-10-02 에 공개 데이터로 새로 학습한 다른 모델이다
  (sha256 `ae95071c…`). 두 모델을 섞어 쓰면 수치와 산출물이 어긋난다.

### ② 현장 설치 실적이 없다

가장 큰 병목이다. 카메라를 **실제 수조에 1~3대 고정**해야 ①의 현장 평가도, ③의 가동률도,
현장 사진도 생긴다. 이 자료집의 그림은 전부 시연 환경에서 뜬 것이다.

### ③ 가동률 실측값이 없다

집계 함수(`supabase/migrations/vision_uptime.sql`)는 만들었고 29건으로 검증했지만,
집계할 **현장 운전 기록이 아직 쌓이지 않았다.** 설치 후 2주면 의미 있는 표가 나온다.
※ 함수가 동작하려면 사람이 Supabase SQL Editor 에서 그 파일을 한 번 실행해야 한다.

### ④ 라이선스 검토

배포 중인 계수 모델은 Ultralytics **AGPL-3.0** 계열이다. 상용 판매 시 검토가 필요하다.

## 5. 자료를 다시 만드는 법

```
# 시험 결과 6종 (10~15분)
./docs/result-03-bluestartup/src/collect-evidence.sh

# 설계·구조 그림 3장
node docs/result-03-bluestartup/src/render-diagrams.mjs

# 웹 화면 5장 (3~5분)
node docs/result-03-bluestartup/src/capture-screens.mjs

# 장비 화면 5장
SHOT_SCALE=2 OUT_DIR=/tmp/kiosk node vision/tests/ui/check_kiosk_screens.js

# 화면 점검이 .next 를 바꿔 두므로, 끝나면 평소 빌드로 되돌린다
VERCEL=1 npx next build
```

필요한 것: `vision/.venv`, node, Chromium, PostgreSQL 16.
