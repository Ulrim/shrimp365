# 수조 조건 데이터 확보 계획

작성 2026-11-11 · 대상 `vision/` · 관련 [`result-03-bluestartup/시험의뢰_패키지.md`](result-03-bluestartup/시험의뢰_패키지.md)

## 0. 무엇이 문제인가

지금 모델이 배운 것은 **쟁반·얼음·흰 배경 위에 놓인 새우 사진**이다(`shrimp_cf`,
한 장에 1~3마리). 우리가 쓰려는 곳은 **물속 수조**다. 둘은 다음이 다르다.

| | 학습 데이터 | 실제 수조 |
|---|---|---|
| 배경 | 균일한 쟁반·얼음 | 탁한 물, 바닥 침전물, 급이대, 그물 |
| 개체 수 | 1~3마리 | 수십 마리, 서로 겹침 |
| 조명 | 실내 균일광 | 주야 변화, 수면 반사, 야간 적외선 |
| 개체 모습 | 전신이 또렷 | 일부만 보임, 흐림, 움직임 번짐 |
| 오검출 유발 | 거의 없음 | 사료 입자, 기포, 그물코, 반사 |

그래서 `test 445장`으로 받은 성적서는 **요건은 충족하지만 현장 성능의 근거는
아니다.** 점검위원이 그림을 보면 바로 묻는다. 이 문서는 그 구멍을 메우는 길이다.

이 데이터는 세 곳에 동시에 쓰인다.

1. **성적서 보강** — 실제 운용 조건의 독립 시험셋
2. **모델 정확도** — 현장 데이터를 넣어 재학습하면 가장 크게 오른다
3. **가동률 증빙** — 카메라가 돌아야 `vision_uptime` 집계에 쓸 운전 기록이 쌓인다

세 번째는 데이터 확보의 부산물이 아니라, **카메라를 거는 순간 저절로 따라온다.**

도구는 다 있다. **수조에 카메라를 거는 일만 남았다.**

### 서버로 올라가는 스냅샷은 데이터셋으로 쓰지 말 것

`snapshot_sender` 가 올리는 사진은 **가로 640px, JPEG 품질 60, 60초 간격**이다
(`app/config.py`). 웹에서 "지금 수조가 어떤가"를 보기엔 충분하지만, 학습·평가용
으로는 안 된다 — 줄이고 다시 압축하면서 작은 개체의 윤곽이 뭉개진다. 그걸로 잰
성능은 실제 장비가 보는 그림의 성능이 아니다.

**원본 해상도 프레임을 장비(파이) 쪽에 따로 저장해 가져온다.**

## 2. 무엇을 모아야 하는가 — 변이 목록

장수보다 **다양성**이 중요하다. 같은 장면 1,000장보다 다른 조건 200장이 낫다.
아래가 빠지면 그 조건에서 조용히 틀린다.

| 조건 | 왜 필요한가 | 최소 회차 |
|---|---|---|
| **주간 자연광** | 기본 조건 | 3 |
| **야간 / 적외선 조명** | 색이 사라지고 흑백이 된다 — 낮 데이터만으로는 못 잡는다 | 3 |
| **급이 직후** | 사료 입자가 새우처럼 보인다. **오검출의 주원인** | 3 |
| **급이 전(공복)** | 새우가 바닥에 퍼져 있다 | 2 |
| **탁도 높음** (환수 전·바닥 교란) | 흐린 물에서 윤곽이 사라진다 | 2 |
| **탁도 낮음** (환수 직후) | 반대쪽 극단 | 2 |
| **밀집** (여러 마리 겹침) | 계수 오차가 가장 커지는 구간 | 3 |
| **희소** (몇 마리) | 작은 수에서 오차율은 한 마리만 틀려도 커진다 | 2 |
| **빈 수조 / 새우 없는 구역** | **정답 0마리.** 헛검출이 몇 개 나오는지 재는 유일한 방법 | 2 |
| **성장 단계** (자어 → 성체) | 몸 크기가 몇 배로 변한다. 한 시점만 모으면 나머지 시기에 틀린다 | 주기 내내 |

마지막 줄이 함정이다. 지금 2주 모아 두면 **그 크기의 새우만** 잘 잡는다. 한
사이클(보통 수개월)에 걸쳐 조금씩 계속 모아야 한다. 이번 과제에는 지금 구간만
쓰되, **수집을 계속 돌려 둔다.**

## 3. 어떻게 모으나

### 3-1. 카메라 고정

- 수조 **1~3대**. 한 대로 시작해도 되지만, 각도·수조가 하나뿐이면 모델이 그
  구도에만 맞춰진다.
- 높이·각도를 **고정하고 기록**한다. 나중에 바꾸면 그 전후가 다른 데이터가 된다.
- 급이대가 화면에 들어오게 둔다 — 실제 운용에서 들어오기 때문이다.
- 야간 조명(적외선)을 켜 둔다.

### 3-2. 프레임 뽑기

장비(파이) 또는 같은 망의 노트북에서:

```bash
cd vision
pip install -e ".[ml]"        # opencv 필요

python ai/trainer/extract_frames.py \
  --source rtsp://<카메라 주소>/stream \
  --out data/tank/raw \
  --every-seconds 300 \
  --limit 24 \
  --prefix tank1-주간-급이후
```

- `--every-seconds 300` = 5분 간격. **연속 프레임은 쓸모가 없다** — 1초 전후
  두 장은 사실상 같은 그림이라, 라벨링 품만 늘고 데이터는 늘지 않는다.
- `--limit 24` = 한 회차 2시간치. **짧게 여러 회차**로 나눠 찍는다(§5 참고).
- `--prefix` 로 조건을 이름에 남긴다. 나중에 "야간만 따로 평가" 가 가능해진다.

파일 이름은 `tank1-주간-급이후.rf.000001.jpg` 꼴이 된다. `.rf.` 앞이 **회차**이고,
이것이 분할의 단위다(§5).

### 3-3. 되도록 영상도 함께 남긴다

프레임만 남기면 나중에 "이 장면 앞뒤가 어땠나"를 못 본다. 가능하면 같은 시간대
원본 영상을 며칠치 보관해 둔다 — 나중에 다른 간격으로 다시 뽑을 수 있다.

## 4. 얼마나 필요한가

| | 라벨 장수 | 회차 | 기간 | 쓸 수 있는 것 |
|---|---|---|---|---|
| **최소판** (이번 과제) | 200~300 | 10~15 | 1주 | 현장 조건 시험셋, 결과보고서에 "현장 1차 검증" |
| **제대로판** | 800~1,500 | 40+ | 한 사이클 | 재학습으로 현장 정확도 확보, 시험기관 독립 시험셋 |

최소판 200~300장은 **재학습용으로는 적다.** 그 숫자의 1차 쓰임새는 "현재 모델이
수조에서 얼마나 하는가"를 **재는 것**이다. 재서 나쁘면 그때 재학습을 말한다.

---

## 5. 분할 — 무작위로 나누면 안 된다

같은 회차 프레임은 5분 간격이어도 물 색·조명·개체 배치가 거의 같다. 무작위로
나누면 학습에서 본 장면을 평가에서 다시 보게 되어 **점수가 부풀려진다.**

그래서 **회차를 통째로** 한 분할에 넣는다. `prepare_dataset.py` 가 `.rf.` 앞부분이
같은 것을 한 묶음으로 보므로, §3-2 의 이름 규칙을 쓰면 자동으로 그렇게 된다
(`vision/tests/test_dataset_prep.py` 가 이 성질을 시험한다).

여기서 따라오는 결론이 하나 있다 — **회차가 적으면 비율을 맞출 수 없다.**
회차 3개로는 train/valid/test 를 못 만든다. 그래서 §3-2 에서 짧게 여러 번 찍으라고
한 것이다. **최소 10회차**를 목표로 한다.

## 6. 라벨링

### 6-1. 순서

```bash
# 1) 지금 모델로 밑그림을 그린다 — 임계값을 낮춰 '과하게' 찍게 한다
#    (--conf 기본값 0.4 는 학습 데이터를 대량으로 만들 때 쓰는 값이다.
#     평가용 정답을 만들 때는 낮춘다 — 이유는 6-2)
python ai/trainer/pseudo_label.py \
  --weights ai/models/shrimp_yolov8n_416.onnx \
  --images data/tank/raw --out data/tank/predabel --conf 0.10

# 2) 결과 폴더를 Roboflow / CVAT 에 올려 사람이 고친다
# 3) YOLOv8 형식으로 내려받아 data/tank/labeled 에 푼다
```

### 6-2. 함정 — 모델이 놓친 것은 사람도 놓친다

사전 라벨을 고치는 방식은 빠르지만, 사람이 **있는 상자를 지우는 일**은 잘 해도
**없는 상자를 새로 그리는 일**은 잘 안 하게 된다. 그러면 모델이 못 보는 새우는
정답에서도 빠지고, **평가는 모델에게 유리하게 기울어진다.**

두 가지로 막는다.

- 사전 라벨을 `--conf 0.10` 으로 **과검출시킨다.** 지우는 작업이 중심이 되게 한다.
- **전체의 10~20%는 백지에서 라벨링**해 대조군으로 둔다. 두 방식의 평균 개체 수가
  크게 다르면, 고치는 방식이 놓치고 있다는 뜻이다.

### 6-3. 라벨 기준을 먼저 정한다

사람마다 다르게 그리면 지표가 흔들린다. 시작 전에 종이 한 장으로 정해 둔다.

- 반쯤 가려진 개체 — 몸통이 **절반 이상** 보이면 그린다
- 화면에 걸친 개체 — 보이는 부분만 감싼다
- 수면 반사로 비친 상 — **그리지 않는다**
- 탈피 껍질 — 그리지 않는다(살아 있는 개체가 아니다)
- 상자 범위 — 더듬이·다리 제외, **몸통(두흉부~꼬리)**만

마지막 줄이 중요하다. 더듬이까지 감싸면 상자가 커져 IoU 가 흔들리고, 사람마다
크게 달라진다.

## 7. 모은 뒤 — 측정과 재학습

### 7-1. 측정(먼저 이것부터)

```bash
cd vision
python ai/trainer/eval_detect.py \
  --weights ai/models/shrimp_yolov8n_416.onnx \
  --images data/tank/labeled/test/images \
  --labels data/tank/labeled/test/labels \
  --conf 0.25 --bootstrap 2000 \
  --json ../docs/result-03-bluestartup/evidence/09_현장수조_측정.json \
  --csv  ../docs/result-03-bluestartup/evidence/09_현장수조_측정_이미지별.csv
```

이 숫자가 **현장 성능**이다. `shrimp_cf` 수치와 나란히 적되 **섞지 않는다.**

눈으로도 본다 — 틀린 장면을 봐야 원인을 안다.

```bash
python ai/trainer/draw_detections.py \
  --weights ai/models/shrimp_yolov8n_416.onnx \
  --images data/tank/labeled/test/images \
  --labels data/tank/labeled/test/labels --out out/현장그림
```

### 7-2. 재학습(필요하면)

```bash
python ai/trainer/prepare_dataset.py \
  --source shrimp_cf=<...> --source counting_pl=<...> --source tank=data/tank/labeled \
  --out datasets/shrimp_v2 --on-leakage regroup
```

현장 데이터는 장수가 적어도 효과가 크다 — 모델이 **한 번도 못 본 조건**이기
때문이다. 학습 뒤에는 §7-1 을 다시 돌려 **같은 시험셋에서** 전후를 비교한다.

## 8. 계수 오차율의 "정답"은 어디서 오나

탐지 지표는 사람이 그린 상자가 정답이다. 그런데 **마리 수**의 정답은 더 조심해야
한다.

- **쓸 수 있는 것** — 사람이 그 프레임에서 센 수(=라벨 개수). 프레임 단위 오차율은
  이것으로 낸다.
- **쓸 수 없는 것** — 입식 마릿수. 폐사·성장으로 실제와 벌어지고, 한 프레임에
  수조 전체가 들어오지도 않는다.
- **별도로 필요한 것** — 관측 영역과 수조 전체의 **면적 보정비**. 프레임 안 마리
  수를 수조 전체로 환산하려면 이 값이 있어야 하고, 이것은 카메라를 고정한 뒤
  실측해야 한다. 지금 결정되지 않은 항목이다.

즉 현장 계수 오차율은 **"관측 영역 안에서 몇 마리를 맞혔나"**까지 말할 수 있고,
"수조에 몇 마리 있나"는 면적 보정비가 정해져야 말할 수 있다. 보고서에서 이 둘을
구분해 적는다.

## 10. 위험

1. **카메라 고정이 늦어진다** — 가장 큰 위험이자 유일한 병목. 늦어지면 현장
   검증 없이 공개 데이터 성적서만으로 보고하게 된다. 그 경우 결과보고서에
   "현장 검증은 차기 과제" 라고 명시한다(숨기면 점검에서 더 크게 걸린다).
2. **현장 성능이 공개 데이터보다 크게 낮다** — 거의 확실히 낮다. 그것이 정상이고,
   그 차이를 **측정해 적는 것**이 이 계획의 목적이다. 낮다고 숨기면 안 된다.
3. **라벨 품질** — §6-2 의 대조군을 생략하면 평가가 모델에 유리하게 기운다.
4. **한 시점만 모은다** — 지금 크기의 새우만 잘 잡게 된다. 수집은 과제가 끝나도
   계속 돌려 둔다.
