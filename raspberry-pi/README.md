# 수질 모니터링 프로그램 — 라즈베리파이

라즈베리파이를 수질 모니터링 장비로 만드는 프로그램입니다.
RS-485 디지털 센서(MODBUS-RTU)에서 **수온·pH·DO·염도**를 읽어 Shrimp365 계정으로 올립니다.
로그인하면 해당 수조의 수질 기록·차트·알림에 자동으로 반영됩니다.

파이 화면에는 현재 수치와 그래프가 뜨고, 인터넷이 끊겨도 값을 보관했다가
회선이 돌아오면 끊겼던 시점부터 이어서 올립니다.

**값을 올리는 데서 그치지 않습니다.** 기준 이탈과 추세 이상징후를 장비 안에서 판정하고,
그 결과를 「산소공급기·브로워 즉시 최대 가동」 같은 **설비 운전 권고 한 줄**로 바꿔
화면에 띄웁니다. 서버도 인터넷도 쓰지 않으므로 회선이 죽은 밤에도 그대로 돕니다
(→ [이상징후 판정과 설비 운전 권고](#이상징후-판정과-설비-운전-권고)).

> **처음 설치하신다면 → [INSTALL.md](INSTALL.md)**
> 빈 SD카드에서 시작해 Shrimp365 화면에 값이 올라오는 것까지 순서대로 적어 두었습니다.
> 이 문서는 기능과 설정 항목을 다룹니다.

지원 센서 — Nengshi 디지털 센서 프로토콜

| 센서 | 기본 슬레이브 ID | 읽는 값 |
|---|---|---|
| pH/ORP | 1 | pH, ORP, 수온 |
| DO | 3 | 용존산소(㎎/L), 포화도(%), 수온 |
| EC/TDS/염도 | 4 | 전도도, TDS, 염도(ppt), 수온 |

수온은 세 센서 모두에 들어 있어서 **하나만** 골라 보냅니다. 같은 값을 겹쳐 보내면
어느 것이 맞는지 알 수 없기 때문입니다. **DO 센서가 있으면 그 수온을 씁니다**
(DO → pH → EC 순). 용존산소는 수온에 따라 포화 농도가 크게 달라져서 변환기가 자기
수온으로 보정해 값을 내는데, 그 보정에 쓰인 수온과 기록에 남는 수온이 다르면
나중에 "이 DO 값이 왜 이런가" 를 따질 때 근거가 어긋나기 때문입니다.
DO 센서가 없을 때만 pH 센서의 수온을 대신 씁니다.

## 1. 준비물

- 라즈베리파이 (Zero 2 W 이상, OS Lite로 충분)
- **USB-RS485 변환기** (권장) 또는 GPIO UART + RS485 트랜시버
- 센서 전원 **DC 9~24V** — 라즈베리파이 5V로는 동작하지 않습니다
- 센서와 변환기를 잇는 4선

## 2. 배선

센서 케이블 색깔은 제조사 문서 기준입니다.

| 선 색 | 연결 |
|---|---|
| 빨강 | DC 9~24V (+) |
| 검정 | 0V (−) |
| 초록 | RS485 **A** (T/R+) |
| 노랑 | RS485 **B** (T/R−) |

**주의할 점**

- 센서 전원의 0V와 라즈베리파이 GND를 **공통으로 묶어** 주세요. 안 그러면 통신이 불안정합니다.
- 센서 여러 대를 **같은 A/B 선에 병렬로** 연결합니다. 각 센서의 슬레이브 ID가 달라야 합니다.
- 선이 10m를 넘으면 양 끝에 **120Ω 종단저항**을 답니다. CRC 오류가 잦으면 이걸 먼저 의심하세요.

## 3. 설치

파이에서 세 줄이면 됩니다. 계정도 토큰도 git 도 필요 없습니다.

```bash
curl -fsSLO https://www.shrimp365.kr/updates/shrimp365-setup-latest.tar.gz
tar xzf shrimp365-setup-latest.tar.gz
cd shrimp365-setup && sudo ./install.sh
```

패키지 설치, 프로그램 배치(`/opt/shrimp365`), 설정 파일 생성(`/etc/shrimp365/config.ini`),
전용 계정 생성, 서비스 등록까지 한 번에 합니다. 설정을 먼저 채워야 하므로 **시작은 하지 않습니다.**

> 빈 SD카드에서 시작하는 전체 절차는 **[INSTALL.md](INSTALL.md)** 에 따로 정리해 두었습니다.
> OS 굽기, 인터넷이 없을 때 받는 방법, 마무리 확인표까지 순서대로 적혀 있습니다.

## 4. 기기 연결

두 가지 방법이 있습니다. **코드로 연결**을 권합니다.

### 방법 1 — 코드로 연결 (권장)

긴 키를 옮겨 적지 않아도 됩니다. 설정 파일의 `device_key`를 **비워 둔 채** 실행하면
기기가 6자리 코드를 화면에 띄웁니다.

```
+--------------------+
|  Pair this device  |
|    4 8 2 1 0 0     |
|www.shrimp365.kr    |
|waiting...          |
+--------------------+
```

1. 농가가 휴대폰이나 터치스크린으로 **Shrimp365 로그인**
2. **양식장·수조 관리** → 수조의 **센서 기기** 펼치기 → **코드로 기기 연결**
3. 화면의 6자리 코드 입력 → 연결

승인되면 기기가 키를 자동으로 받아 설정 파일에 저장하고, 곧바로 측정을 시작합니다.

> 코드는 **15분간** 유효합니다. 지나면 기기가 알아서 새 코드를 띄웁니다.
> 승인 전까지 기기는 어떤 데이터도 올릴 수 없습니다.

**왜 이메일이 아니라 코드인가**
이메일 주소는 명함·게시판 어디에나 있는 공개 정보입니다. 이메일만으로 기기를 지정하면
누구나 남의 계정에 가짜 수질값을 밀어 넣을 수 있습니다. 수질 데이터는 알림과 판단의
근거이므로, 승인은 **로그인한 계정 주인만** 할 수 있어야 합니다.

### 방법 2 — 키를 직접 붙여넣기

**기기 등록** 버튼으로 발급받은 키를 설정 파일에 적습니다. 키는 발급 직후 한 번만 표시됩니다.

```ini
[server]
endpoint   = https://www.shrimp365.kr/api/sensors/data
device_key = 발급받은_키
interval_seconds = 60       ; 1분마다 측정

[serial]
port = /dev/ttyUSB0         ; USB 변환기. GPIO UART면 /dev/serial0

[sensors]
ph_enabled = true
ph_slave_id = 1
do_enabled = true
do_slave_id = 3
ec_enabled = true
ec_slave_id = 4
```

연결하지 않은 센서는 `false`로 두세요.

## 5. 동작 확인

서버로 보내기 전에 값이 제대로 읽히는지 먼저 봅니다.

```bash
# 읽기만 하고 전송하지 않음
sudo python3 /opt/shrimp365/shrimp365_sensor.py \
  --config /etc/shrimp365/config.ini --once --dry-run -v
```

정상이면 이런 값이 나옵니다.

```json
{
  "ph": 7.85,
  "orp": 210.0,
  "do_level": 6.42,
  "do_saturation": 84.1,
  "conductivity": 32.1,
  "tds": 16.05,
  "salinity": 21.4,
  "temperature": 28.4
}
```

값이 맞으면 실제로 한 번 보내 봅니다.

```bash
sudo python3 /opt/shrimp365/shrimp365_sensor.py \
  --config /etc/shrimp365/config.ini --once -v
```

`전송 완료`가 뜨면 Shrimp365 화면의 기기 카드에 **방금 전**과 측정값이 표시됩니다.

## 6. 상시 실행 등록

```bash
sudo useradd -r -G dialout -s /usr/sbin/nologin shrimp365 || true
sudo cp shrimp365-sensor.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now shrimp365-sensor

# 상태·로그 확인
systemctl status shrimp365-sensor
journalctl -u shrimp365-sensor -f
```

정전이나 재부팅 후에도 자동으로 다시 시작합니다. 인터넷이 끊겨도 프로세스는 살아 있고 다음 주기에 다시 시도합니다.

## LCD 화면 붙이기 (선택)

라즈베리파이에 **I2C 문자 LCD**(1602 또는 2004)를 달면 현장에서 바로 값을 볼 수 있습니다.
인터넷이 끊겨도 화면에는 계속 표시됩니다.

### 배선 (I2C 4선)

| LCD 백팩 | 라즈베리파이 |
|---|---|
| VCC | 5V (2번 핀) |
| GND | GND (6번 핀) |
| SDA | GPIO2 (3번 핀) |
| SCL | GPIO3 (5번 핀) |

### I2C 켜기

```bash
sudo raspi-config       # Interface Options → I2C → Yes
sudo apt install -y i2c-tools
sudo i2cdetect -y 1     # 27 또는 3f 가 보이면 정상
```

`27`이 보이면 주소는 `0x27`, `3f`면 `0x3F`입니다.

### 설정

`/etc/shrimp365/config.ini`

```ini
[display]
type = i2c_lcd
columns = 16          ; 1602 이면 16, 2004 이면 20
rows = 2              ; 1602 이면 2,  2004 이면 4
i2c_bus = 1
i2c_address = 0x27
page_seconds = 5      ; 값이 다 안 들어갈 때 넘기는 간격
```

`shrimp365` 사용자를 i2c 그룹에 넣어 줍니다.

```bash
sudo usermod -aG i2c shrimp365
sudo systemctl restart shrimp365-sensor
```

### 표시되는 모습

**2004 (20x4)** — 네 값이 한 화면에

```
+--------------------+
|Temp           28.4C|
|pH              7.85|
|DO          6.42mg/L|
|Sal          21.4ppt|
+--------------------+
```

**1602 (16x2)** — 두 개씩 5초마다 번갈아

```
+----------------+     +----------------+
|Temp       28.4C|     |DO      6.42mg/L|
|pH          7.85|  →  |Sal      21.4ppt|
+----------------+     +----------------+
```

**문제가 생기면** 값 한 줄을 밀어내고 경고를 띄웁니다.
현장에서는 "지금 안 올라가고 있다"는 사실이 값 하나보다 중요합니다.

```
+--------------------+
|Temp           28.4C|
|pH              7.85|
|DO          6.42mg/L|
|SEND FAIL 14:32     |
+--------------------+
```

| 표시 | 뜻 |
|---|---|
| `sent 14:32` | 14시 32분에 서버 전송 성공 |
| `SEND FAIL 14:32` | 서버 전송 실패 (인터넷·키 확인) |
| `SENSOR ERROR` | 센서를 하나도 읽지 못함 (배선·전원 확인) |
| `No sensor data` | 아직 첫 측정 전 |

### 알아 두실 점

**한글은 표시되지 않습니다.** 문자 LCD는 폰트가 칩 안에 고정돼 있어 한글 글꼴이 없습니다.
그래서 라벨을 `Temp` `pH` `DO` `Sal` 로 씁니다.
한글을 꼭 쓰셔야 하면 **OLED(SSD1306)** 나 소형 HDMI 화면이 필요합니다 — 말씀 주시면 추가하겠습니다.

**LCD가 고장 나도 수집은 멈추지 않습니다.** 화면 초기화나 출력이 실패하면 로그만 남기고
측정·전송은 그대로 계속합니다.

### 배선 전에 미리 보기

LCD를 연결하기 전에 무엇이 표시될지 터미널에서 확인할 수 있습니다.

```ini
[display]
type = console
columns = 20
rows = 4
```

```bash
sudo python3 /opt/shrimp365/shrimp365_sensor.py \
  --config /etc/shrimp365/config.ini --once --dry-run
```

## 7인치 터치스크린 (공식 디스플레이)

라즈베리파이 공식 7인치(800×480)를 달면 장비 자체가 상황판이 됩니다.
수집기가 자체 상태 페이지를 띄우고, 크로미움이 키오스크 모드로 그 페이지를 표시합니다.

**기본 화면은 언제나 측정값입니다.** 계정에 연결했든 안 했든, 인터넷이 있든 없든
눈앞의 수질값이 먼저 보입니다. 연결 코드는 오른쪽 아래 **기기 연결** 버튼을 눌렀을 때만 뜹니다.

**연결 전** — 측정은 그대로, 상단에 "미연결" 표시

```
┌──────────────────────────────────────────────┐
│ 🦐 Shrimp365              10000000c0ffee01   │
│                                              │
│           기기를 연결해 주세요                 │
│      Shrimp365에 로그인한 뒤 코드를 입력       │
│                                              │
│              4 8 2 1 0 0                     │
│                                              │
│   1. www.shrimp365.kr 접속                   │
│   2. 로그인 → 양식장·수조 관리                 │
│   3. 센서 기기 → 코드로 기기 연결              │
│   4. 위 6자리 코드 입력                       │
│ ● 연결 대기 중                                │
└──────────────────────────────────────────────┘
```

**연결 후** — 상단에 어느 계정·양식장·수조에 붙어 있는지 표시

```
┌──────────────────────────────────────────────┐
│ 🦐 Shrimp365  ky****4@gmail.com 1양식장·A-1조 │
│  ┌───────────────┐  ┌───────────────┐        │
│  │ 수온           │  │ pH            │        │
│  │ 28.4 °C       │  │ 7.85          │        │
│  └───────────────┘  └───────────────┘        │
│  ┌───────────────┐  ┌───────────────┐        │
│  │ 용존산소       │  │ 염도           │        │
│  │ 6.42 mg/L     │  │ 21.4 ppt      │        │
│  └───────────────┘  └───────────────┘        │
│ ● sent 14:32                       14:32:05  │
└──────────────────────────────────────────────┘
```

적정 범위를 벗어나면 해당 칸의 테두리와 숫자가 **주황(주의)·빨강(위험)**으로 바뀝니다.

### 화면에서 센서 설정 고치기

오른쪽 아래 **설정** 버튼을 누르면 SSH 없이 화면에서 바로 고칠 수 있습니다.
현장에서는 수조 옆에 선 채로 고쳐야지, 노트북을 들고 와 접속할 일이 아닙니다.

```
┌──────────────────────────────────────────────┐
│ 센서 설정                  /dev/ttyUSB0 [닫기] │
│ ┌──────────────────────────────────────────┐ │
│ │ 선에서 찾은 센서                          │ │
│ │ ID 1 — pH 센서 (첫 값 7.85 pH)            │ │
│ │ ID 4 — EC 센서 (첫 값 32.1 mS)            │ │
│ │ ID 5 — DO 센서 (첫 값 6.42 mg/L)          │ │
│ └──────────────────────────────────────────┘ │
│  pH / ORP        [켬]  [−]  1  [+]           │
│  용존산소         [켬]  [−]  5  [+]           │
│  전도도 / 염도    [켬]  [−]  4  [+]           │
│  측정 주기             [−] 60  [+]           │
│ [선 훑기]  [저장]                             │
└──────────────────────────────────────────────┘
```

- **자동 배치** — 센서를 꽂아 둔 채로 누르면 **값이 나오는 자리를 그대로 배정**합니다.
  매뉴얼 기본값(pH=1, DO=3, EC=4)과 다르게 출고된 물건이 흔하므로, 번호를 하나씩
  맞춰 볼 필요 없이 이것부터 눌러 보시면 됩니다. 화면의 숫자만 채우고 **저장은
  사람이 누릅니다** — 무엇이 바뀌는지 보고 나서 정하시라는 뜻입니다.
- **선 훑기** — 선에 실제로 물려 있는 센서를 찾아 ID와 종류를 보여 줍니다.
  `mg/L` 이면 DO, `mS` 면 EC 라는 식으로 짚어 주므로 어느 번호가 무엇인지 바로 압니다.
- **켬/끔** — 연결하지 않은 센서는 꺼 두세요.
- **± 버튼** — 슬레이브 ID와 측정 주기를 손가락으로 조절합니다.
- **저장** — **다음 측정부터 바로 적용**됩니다. 재시작이 필요 없습니다.
  설정 파일에도 남으므로 재부팅해도 유지됩니다.

같은 ID가 둘이거나, 센서를 모두 끄거나, 주기가 60초 미만이면 저장을 거부하고
이유를 알려 줍니다. 잘못 눌러 측정이 멎는 일이 없도록 하기 위함입니다.

**자동 배치가 못 하는 것** — 같은 종류가 두 자리에서 응답하면 어느 쪽을 쓸지
알 수 없으므로 그대로 두고 알려 줍니다. 못 찾은 센서는 꺼 둡니다. 달아 두셨는데
안 잡혔다면 전원·배선을 보시거나, 같은 번호를 쓰는 센서가 없는지 확인하세요
(같은 번호가 둘이면 하나가 다른 하나를 가려 아예 안 보입니다).

터미널에서도 같은 일을 할 수 있습니다. 이쪽은 곧바로 설정 파일에 씁니다.

```bash
sudo -u shrimp365 python3 /opt/shrimp365/shrimp365_sensor.py \
  --config /etc/shrimp365/config.ini --auto
```

> 훑는 동안에는 측정이 잠깐 기다립니다. 센서 여러 대가 같은 선을 쓰기 때문에
> 훑기와 측정이 겹치면 둘 다 엉뚱한 응답을 받습니다.

### 화면에서 Wi‑Fi 붙이기

오른쪽 아래 **Wi‑Fi** 버튼을 누르면 SSH 없이 화면만 보고 공유기를 바꿔 붙일 수 있습니다.

- 주변 공유기를 **검색**해 신호 세기 순으로 보여 줍니다. 지금 붙어 있는 곳은 위에
  초록색으로 표시됩니다.
- 잠긴 공유기를 고르면 **화면 키보드**가 뜹니다 — 터치스크린에는 물리 키보드가 없으므로
  비밀번호를 손가락으로 넣도록 페이지 안에 키보드를 넣어 두었습니다. 대소문자(⇧)·숫자·기호(`?123`)를
  오갈 수 있고, **표시**를 누르면 입력한 비밀번호를 확인할 수 있습니다.
- 열린 공유기(자물쇠 없음)는 고르면 바로 붙습니다.

동작 방식과 권한

- 라즈베리파이 OS(Bookworm 이후)의 **NetworkManager**(`nmcli`)를 그대로 씁니다.
- 수집기는 로그인 세션 없는 서비스 계정(`shrimp365`)으로 돌기 때문에, 화면에서 Wi‑Fi 를
  **바꾸려면** NetworkManager 제어 권한이 필요합니다. `install.sh` 가 polkit 규칙
  (`/etc/polkit-1/rules.d/50-shrimp365-nm.rules`)을 깔아 이 계정에만 그 권한을 줍니다.
- 규칙이 없으면 조회·검색은 대개 되지만 접속에서 **"권한이 없어 바꾸지 못했습니다"** 가 뜹니다.
  다만 이 규칙은 **원격 업데이트가 자동으로 깔아 줍니다** — 업데이터(루트)가 돌 때마다
  polkit 규칙과 systemd 타이머를 정본과 맞추므로, 사람이 `install.sh` 를 다시 돌리지 않아도
  됩니다(updater.py 의 `ensure_system_files`). 최초 1회 업데이트를 받은 뒤 자동으로 반영됩니다.

> 기기에 무선 장치가 없거나 NetworkManager 를 쓰지 않으면 Wi‑Fi 버튼은 그대로 두되
> "이 기기에서 Wi‑Fi 설정을 지원하지 않습니다" 라고 알립니다.

### 그래프 보기

측정값 칸을 **누르면** 그 항목의 그래프가 열립니다. 구간은 **6시간 · 12시간 · 24시간 · 일주일** 중에 고릅니다.

```
┌──────────────────────────────────────────────┐
│ 용존산소  5.64 mg/L      최저 3.06 평균 6.40  │
│ [6시간][12시간][24시간][일주일]        [닫기] │
│ ┌──────────────────────────────────────────┐ │
│ │        ╱‾‾‾‾╲                            │ │
│ │ ─────╱────────╲──────── 적정 범위 (녹색) │ │
│ │    ╱            ╲___                     │ │
│ │                     ╲__╱  ← 새벽 급락    │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

- **녹색 띠**가 적정 범위입니다. 선이 띠 밖으로 나가면 눈으로 바로 보입니다.
- 선 주변의 옅은 영역은 그 구간의 **최저~최고** 폭입니다. 평균만 그리면
  짧게 스친 위험값이 사라지기 때문입니다.
- 이력은 파이에 따로 보관하므로 **인터넷이 끊겨 있어도** 그래프가 나옵니다.

```ini
[history]
enabled = true
path = /var/lib/shrimp365/history.db
retention_days = 8      ; 화면에서 최대 일주일까지 보므로 여유를 둠
```

### 왜 Shrimp365 사이트를 바로 띄우지 않는가

두 가지 이유입니다.

- **연결 전에는 코드를 띄울 자리가 필요합니다.** 브라우저가 사이트를 차지하면
  아직 연결되지 않은 기기는 코드를 보여줄 방법이 없습니다.
- **인터넷이 끊겨도 값은 보여야 합니다.** 정작 수질값이 급한 순간이 회선이 죽었을 때입니다.
  상태 페이지는 파이 안에서 도는 것이라 회선과 무관하게 계속 갱신됩니다.

최근 일주일까지는 위 그래프로 장비에서 바로 봅니다. 그보다 오래된 이력이나
여러 수조 비교가 필요하면 같은 화면에서 브라우저 주소만 바꿔 Shrimp365에 접속하면 됩니다.

### 키오스크 설치

데스크톱이 있는 Raspberry Pi OS에서 실행합니다(Lite 버전에는 데스크톱이 없습니다).

```bash
sudo ./setup-kiosk.sh
sudo reboot
```

이 스크립트가 하는 일

- **상태 페이지 켜기** (`[webui] enabled = true`) 후 수집기 재시작
- 크로미움·한글 글꼴 설치, 키오스크 실행 스크립트 생성
- 부팅 시 자동 실행 등록 (Wayland·X11 환경 모두 대응)
- 화면 절전·꺼짐·마우스 커서 비활성화
- 정전 후 뜨는 "복원하시겠습니까?" 안내 제거

상태 페이지 설정은 `/etc/shrimp365/config.ini` 에서 바꿀 수 있습니다.

```ini
[webui]
enabled = true
port = 8080
```

재부팅 없이 바로 확인하려면

```bash
/usr/local/bin/shrimp365-kiosk
```

### 알아 두실 점

문자 LCD와 달리 **한글이 그대로 나옵니다.** 두 화면을 동시에 쓸 수도 있습니다
(`[display]` 는 LCD, `[webui]` 는 터치스크린).

## 원격 소프트웨어 업데이트

현장에 나간 장비를 매번 찾아다닐 수 없으니 인터넷으로 새 버전을 받습니다.
다만 이 기능은 성격상 **남의 장비에서 코드를 실행하는 통로**라, 두 겹으로 막아 두었습니다.

```
[오너 PC]  새 버전에 개인키로 서명 ──▶ 웹사이트에 파일로 올림
                                            │
[장비] 5분마다 확인 ──▶ 서버: "1.1.0 을 승인했다" (번호만)
       내려받기 ──▶ 해시 확인 ──▶ 서명 확인 (공개키는 장비 안에 박혀 있음)
       ──▶ 문법·불러오기 점검 ──▶ 교체 ──▶ 재시작 ──▶ 자리 잡았는지 확인
                                                  └─ 아니면 이전 버전으로 자동 복구
```

**승인한 기기만 받아 갑니다.** 웹의 기기 카드에서 **[업데이트]** 를 누른 기기만
다음 확인 때 가져갑니다. 장비는 **5분마다** 확인하므로 누르면 대개 몇 분 안에
자동으로 적용됩니다. 누르지 않으면 아무 일도 일어나지 않습니다.
한 대에서 먼저 해 보고 괜찮으면 나머지를 올리는 식으로 쓰시면 됩니다.

> 확인 주기(5분)는 systemd 타이머(`shrimp365-update.timer`)에 있습니다. 이 타이머와
> polkit 규칙 같은 시스템 파일은 업데이터(`updater.py` 의 `ensure_system_files`)가
> 매 실행 때 정본과 맞추므로, 주기·권한을 바꿔도 **원격 업데이트만으로 자동 반영**됩니다
> — 사람이 `install.sh` 를 다시 돌릴 필요가 없습니다. (정본은 updater.py 안에 내장돼
> 서명된 꾸러미로 전달되고, release.py 가 배포 때 원본과 같은지 확인합니다.)

**서버가 뚫려도 코드를 심을 수 없습니다.** 꾸러미가 진짜인지는 서버가 아니라
**서명**이 보장합니다. 서명은 오너 PC 의 개인키로만 만들 수 있고, 공개키는 장비
안에 박혀 있습니다. 서버가 할 수 있는 말은 "몇 번 버전을 허용했다" 는 번호뿐입니다.
현재보다 낮은 버전은 받지 않으므로, 이미 서명된 옛 꾸러미를 다시 미는 수법도 막힙니다.

**실패하면 되돌립니다.** 새 버전이 재시작 후 자리를 잡지 못하면 이전 버전으로
되돌리고 다시 시작합니다. 수질 감시 장비가 업데이트 한 번에 먹통이 되는 편이
구버전으로 도는 것보다 훨씬 나쁩니다.

**터치스크린은 스스로 새로고침합니다.** 업데이트로 서비스가 재시작되면 화면(키오스크)이
버전이 바뀐 것을 감지해 자동으로 새로고침하므로, 사람이 장비를 만지지 않아도 새 UI 가
바로 뜹니다. 웹의 기기 카드에는 현재/최신 버전이 표시되고, 이미 최신이면 "최신 버전입니다"
로만 보이며 업데이트를 권하지 않습니다(최신에는 자동 적용도 하지 않습니다).

### 설정

```ini
[update]
enabled = true
```

끄시려면 `false`. 꺼도 측정·전송은 그대로입니다.

### 확인·수동 실행

```bash
# 다음 확인 예정 시각
systemctl list-timers shrimp365-update

# 지금 바로 확인 (승인해 둔 것이 있으면 즉시 적용)
sudo systemctl start shrimp365-update

# 무슨 일이 있었는지
journalctl -u shrimp365-update -n 50

# 적용하지 않고 확인만
sudo python3 /opt/shrimp365/updater.py --dry-run -v
```

기기마다 최대 6시간을 무작위로 늦춰서 확인합니다. 전 농가가 같은 시각에 몰리면
서버도 회선도 한꺼번에 부담을 받기 때문입니다.

### 새 버전 배포하기 (오너)

```bash
# 처음 한 번 — 서명 열쇠 만들기
python3 raspberry-pi/release.py init
#   → 나온 공개키를 raspberry-pi/updater.py 의 RELEASE_PUBLIC_KEY 에 붙여 넣기

# 새 버전 낼 때마다
python3 raspberry-pi/release.py build 1.1.0 --notes "그래프 추가"
git add public/updates raspberry-pi/shrimp365_sensor.py
git commit -m "장비 1.1.0 배포" && git push
```

배포는 파일을 올리는 것으로 끝납니다. 웹사이트가 그대로 서빙합니다.

> **개인키(`~/.shrimp365/release-key.pem`)를 그 PC 밖으로 내보내지 마세요.**
> 이 열쇠가 새어 나가면 그 순간부터 누구든 농가 장비에 코드를 심을 수 있습니다.
> 잃어버리면 새 업데이트를 배포할 수 없게 됩니다(장비의 측정은 계속됩니다).

### 이미 1.8.0 이 돌고 있는 장비가 있다면 — 두 번에 나눠 배포

**새로 설치하는 장비에는 해당하지 않습니다.** `install.sh` 로 처음 깔면 모든 파일이
한꺼번에 들어가므로 바로 1.9.0 을 쓰면 됩니다. 아래는 **이미 현장에 나가 있어 원격
업데이트로만 닿을 수 있는** 1.8.0 장비 이야기입니다.

꾸러미를 검사하는 것은 **장비가 지금 가진 updater.py** 입니다. 1.8.0 까지는 받을 수
있는 파일 이름을 하나하나 적어 두었기 때문에, 1.9.0 이 새로 들고 오는
`limits.py`·`anomaly.py`·`advice.py` 를 보면 "허용되지 않은 파일" 로 **꾸러미 전체를
거부**합니다. 장비가 깨지지는 않지만 영영 1.8.0 에 머뭅니다.

그래서 다리를 한 번 놓습니다.

```bash
# ① 다리 — 업데이트 꾸러미에 updater.py + shrimp365_sensor.py 만 담는다.
#    둘 다 1.8.0 의 허용 목록에 이미 있어 통과한다.
python3 raspberry-pi/release.py build 1.8.1 --bridge --notes "업데이트 검사 규칙 정비"

# ② 농가들이 ①을 적용한 것을 확인한 뒤 본 버전
python3 raspberry-pi/release.py build 1.9.0 --notes "현장 이상징후 판정·설비 운전 권고"
```

`--bridge` 를 빠뜨리면 1.8.1 꾸러미에도 새 모듈이 들어가 **똑같이 거부됩니다.**

①을 받은 장비는 잠시 "새 수집기 + 옛 화면" 이 됩니다. 새 수집기는 `anomaly`·`advice`
를 못 찾으면 조용히 건너뛰고(선택 import), 옛 화면은 모르는 상태 키를 무시하므로
②가 올 때까지 멀쩡히 돕니다. 화면에 운전 권고가 뜨는 것은 ② 부터입니다.

`shrimp365_sensor.py` 가 다리에 함께 들어가는 것은 1.8.0 의 검사 절차 때문입니다 —
꾸러미를 푼 자리에서 `import shrimp365_sensor` 를 해 보므로, 그 파일이 없으면
다리 꾸러미가 "불러오기 실패" 로 튕깁니다.

1.8.1 부터는 파일 이름을 **모양으로** 검사하므로(소문자·숫자·밑줄로만 된 `.py`),
앞으로 모듈이 늘어도 이 과정을 다시 거치지 않습니다.

## 이상징후 판정과 설비 운전 권고

장비는 값을 보여 주는 데서 멈추지 않고 **스스로 판단해 무엇을 돌릴지** 말합니다.
세 층이 겹쳐 있습니다.

| 층 | 무엇을 보나 | 언제 도나 | 파일 |
|---|---|---|---|
| 기준 이탈 | 지금 값이 밴드 밖인가 | 매 측정 | `limits.py` |
| 추세 이상징후 | 값의 **움직임**이 평소와 다른가 | 5분마다 | `anomaly.py` |
| 설비 운전 권고 | 그래서 무엇을 돌릴까 | 매 측정 | `advice.py` |

### 화면의 「AI 모드」 표시

머리에 **`⬤ AI 모드`** 가 늘 떠 있습니다. 평소 화면은 숫자 넉 장뿐이라, 이 장비가
값만 보여 주는 계측기가 아니라는 사실이 보이지 않기 때문입니다.

**눌러 보세요.** 지금 무엇을 하고 있는지가 열립니다 — 세 층 각각의 이름과 설명,
그리고 **지금 몇 건이 걸려 있는지**(기준 이탈 n건 / 이상징후 n건 / 운전 권고 n건),
추세를 몇 시간치 몇 개 점으로 보고 있는지, 마지막 분석이 언제였는지.

표시가 **꺼짐**이면 판정 모듈이나 측정 이력이 없는 것입니다. 그때도 측정과 전송은
그대로 됩니다 — 꺼진 것은 판정뿐입니다. 화면이 제멋대로 "켜짐" 이라고 하지 않도록,
수집기가 실제로 세 가지(`anomaly.py`·`advice.py`·이력 DB)를 다 들고 있을 때만
켜진 것으로 보냅니다.

> 여기서 말하는 AI 에 **학습된 모델은 없습니다.** 규칙 기반 위험판정과 통계적
> 이상탐지(급변·연속 악화·3σ 이탈)이고, 그래서 라즈베리파이에서 가볍게 돕니다.
> 학습 모델이 필요한 쪽은 카메라 개체수 세기(`vision/`)이고 그건 별도 장비입니다.

### 왜 추세까지 보나

임계값만 보면 늦습니다. 용존산소가 7.0 에서 5.2 로 떨어지는 동안은 어느 기준도
넘지 않아 화면이 조용하지만, 그 기울기가 그대로면 두 시간 뒤는 폐사 구간입니다.
그래서 값 하나가 아니라 값의 움직임을 봅니다.

- **급변(surge)** — 짧은 간격 안에서 크게 튀었다. 환수 사고·전극 이탈·정전
- **연속 악화(drift)** — 한 방향으로 계속 간다. 유기물 축적·폭기 효율 저하
- **범위 이탈(deviation)** — 이 수조의 평소 분포(3σ)를 벗어났다

**하루 주기는 일부러 잡지 않습니다.** 용존산소는 낮에 오르고 새벽에 떨어지는 것이
정상이라, 그 기울기를 이상이라고 부르면 해 질 녘마다 경보가 울리고 곧 아무도
경보를 보지 않게 됩니다. 수온·pH·용존산소는 **날짜별 극값이 며칠에 걸쳐** 나빠질
때만 연속 악화로 봅니다.

판정은 웹(`lib/thresholds.ts` 의 `detectTrendAnomalies`)과 **같은 구현**입니다.
기준이 두 벌이면 장비와 웹이 서로 다른 말을 하게 되므로 상수와 분기를 그대로
옮겼습니다. 한쪽을 고치면 다른 쪽도 같이 고쳐야 합니다.

### 권고는 무엇을 말하나

| 상황 | 화면에 뜨는 말 |
|---|---|
| 용존산소 4.0 미만 | 산소공급기·브로워 즉시 최대 가동 · 급이 중단 |
| 용존산소 5.0 미만 | 브로워 가동 — 폭기량 20~30% 증대 |
| 기준 안인데 내려가는 중 | 용존산소 하락 중 — 폭기 증대 준비 |
| 산소가 한 시간 넘게 남음 | **과잉 폭기 — 브로워 출력·가동시간 점검** |
| pH 7.0 미만 / 9.0 초과 | 즉시 환수 · 알칼리도 점검 |
| 탁도 상승 | 순환펌프·여과장치 점검 · 역세척 |
| 수온 32 ℃ 초과 / 25 ℃ 미만 | 차광·냉각 가동 / 히터 가동 점검 |

굵게 쓴 줄이 **전력을 줄이라고** 말하는 유일한 자리입니다. 산소가 충분한데 폭기를
계속 돌리는 것은 전력만 쓰는 일이지만, 한 번 높게 찍혔다고 폭기를 줄이게 하면 그
조언 한 번이 수조 하나를 잃게 할 수 있습니다. 그래서 **한 시간 이상 지속**되고
표본이 충분할 때만 말합니다.

**릴레이를 직접 당기지는 않습니다.** 설비를 잘못 돌리는 쪽이 늦게 돌리는 쪽보다
나쁠 수 있고(히터 오동작·펌프 공회전), 현장 설비 구성이 농가마다 다릅니다.
자동제어는 후속 단계입니다.

### 추세 경고는 휴대폰까지 갑니다

이상징후는 장비 화면에만 뜨면 소용이 적습니다. 새벽 세 시에 그 화면을 보는 사람은
없기 때문입니다. 그래서 장비가 찾은 것을 **측정값과 함께 올려** 서버가 알림으로
만들고, 기존 수질 알림과 같은 경로로 휴대폰까지 밀어 줍니다.

```
장비: 급변 감지 ──▶ 측정값에 ai_anomaly 를 실어 전송
서버: 알림 생성 ──▶ 알림함 · 푸시          (알림 이름 "DO 추세")
```

- **알림 이름이 다릅니다.** 임계값 알림은 `DO`, 추세 알림은 `DO 추세` 입니다.
  같은 이름을 쓰면 둘이 한 줄을 두고 다투어 한쪽이 다른 쪽을 덮습니다.
- **수조 색은 바뀌지 않습니다.** 초록·주황·빨강은 지금 값의 판정만 따릅니다.
  기준 안에서 도는 수조가 추세 경고 때문에 "위험" 으로 보이면 진짜 이탈과
  구분되지 않습니다.
- **밀린 값으로는 울리지 않습니다.** 회선이 돌아오면 보관분이 한꺼번에 올라가는데,
  사흘 전 급락으로 지금 휴대폰이 울리면 그 알림은 거짓말입니다. 15분 이내에 잰
  값만 추세 알림이 됩니다.
- **장비 말을 그대로 믿지는 않습니다.** 서버는 항목·종류·등급만 받고 문구는 직접
  짓습니다 — 기기 키를 쥔 쪽이 알림함에 아무 글이나 띄우지 못하게.
- 수경재배(농업) 베드에서는 보내지 않습니다. 추세 기준이 새우 해수 기준이라
  근권 냉방으로 일부러 흔드는 양액에 대면 정상 운전이 경고가 됩니다.

### 판정 숫자는 한 곳에만 있습니다

화면의 색, 운전 권고, 서버가 알림을 만드는 기준이 **같은 숫자**여야 합니다.
셋이 어긋나면 수조 옆 화면은 주황인데 웹은 조용해집니다 — 실제로 수온이 그랬습니다
(장비 정상 28~32 ℃ / 서버 정상 25~32 ℃ 라 26~27 ℃ 구간이 서로 달랐습니다).

지금은 `limits.py` 한 곳에 모아 두고 화면 JS 가 그 표를 주입받아 씁니다.
웹(`lib/thresholds.ts`)과 맞추는 일은 아직 사람이 합니다 — 바꿀 때 양쪽을 함께 고치세요.

### 확인

센서도 인터넷도 없이 판정만 돌려 봅니다. 성능검증 기록지에 붙일 근거로도 씁니다.

```bash
# 개발 PC — 저장소에서
python3 raspberry-pi/verify.py

# 장비에서 — 설치본에 함께 들어갑니다 (점검 자리에서 바로 돌려 보일 수 있게)
python3 /opt/shrimp365/verify.py

# 72시간치(4,320건)를 실제로 적재해 보이려면
python3 /opt/shrimp365/verify.py --full
```

판정 밴드가 서버와 같은지(경계값 16개), 이상탐지가 잡아야 할 것과 **잡지 말아야 할
것**을 둘 다 지키는지, 권고가 상황별로 맞게 나오는지, 재전송 큐가 끊긴 동안의 값을
순서대로 지키는지, 그리고 이력 DB 부터 권고까지 전 구간이 이어지는지를 차례로
확인하고 결과를 표로 찍습니다. 기본 48항목, `--full` 이면 50항목입니다.

**재전송 큐 절(⑥)이 「72시간 저장」 정량목표를 받칩니다.** 그 목표가 묻는 것은 보관
용량이 아니라 *끊겼다 돌아왔을 때 그 사이 값이 순서대로 다 올라가는가* 이고, 용량은
상수를 보면 되지만 나머지는 돌려 봐야 압니다. 넣은 만큼 쌓이는지, 오래된 것부터
나오는지, 올린 만큼 줄고 다음이 이어지는지, **재시작 뒤에도 남아 있는지**(정전 대비),
상한을 넘으면 **오래된 쪽**을 버리는지(최신을 버리면 사고 직전 기록이 날아갑니다),
깨진 행 하나가 뒤의 전부를 막지 않는지를 봅니다.

`--full` 은 파이의 SD카드에서 수십 초 걸립니다 — append 하나가 커밋 하나라서입니다.
점검 자리에서 전체를 빠르게 보일 때는 기본으로, 72시간 적재 자체를 보여야 할 때만
`--full` 로 돌리세요.

> 이 시험이 대신하지 못하는 것 — **실제 72시간 통신 차단 시험**입니다. 여기서 보이는
> 것은 큐의 동작이고, 현장에서 사흘간 끊어 두고 복구를 확인하는 것은 따로 해야 합니다.

## 인터넷이 끊겼을 때

회선이 죽어도 센서는 계속 돕니다. 그동안의 값을 버리면 그래프에 구멍이 남고,
정작 사고가 났던 시간대의 기록이 사라집니다. 그래서 전송하지 못한 값을
라즈베리파이에 저장해 두었다가 **연결이 돌아오면 끊겼던 시점부터 순서대로** 올립니다.

```
회선 끊김 ──▶ 측정은 계속 · 값은 파이에 보관 (화면에 "보관 37건")
회선 복구 ──▶ 오래된 것부터 순서대로 재전송 ("sent +37")
              → 서버 그래프에 그 시간대가 그대로 채워짐
```

계정에 **연결하기 전**에 측정한 값도 함께 보관했다가, 연결하는 순간 올립니다.

### 설정

```ini
[buffer]
enabled = true
path = /var/lib/shrimp365/queue.db
max_rows = 43200      ; 1분 간격이면 약 30일치
flush_batch = 40      ; 한 주기에 올릴 밀린 건수
```

- 저장은 **SQLite**입니다. 파이썬에 내장이라 따로 설치할 것이 없고, 정전이 나도 파일이 깨지지 않습니다.
- 상한을 넘으면 **가장 오래된 것부터** 버립니다. 디스크가 가득 차 파이가 멈추는 쪽이 더 나쁩니다.
- 한 번에 40건씩만 올립니다. 서버가 기기당 분당 60회로 제한하기 때문에 한꺼번에 쏟으면 막힙니다.
  실제 시간의 40배 속도라, 하루치가 밀려 있어도 **약 36분**이면 다 따라잡습니다.
- 재전송 중 다시 끊기면 그 자리에서 멈추고, 다음 기회에 이어서 보냅니다. 순서가 뒤섞이지 않습니다.

### 확인

```bash
# 몇 건이 밀려 있는지 (sqlite3 명령이 없어도 되도록 파이썬으로)
sudo -u shrimp365 python3 -c "import sqlite3;print(sqlite3.connect('/var/lib/shrimp365/queue.db').execute('select count(*) from readings').fetchone()[0])"
```

화면 오른쪽 위의 **보관 N건** 칩으로도 바로 확인할 수 있습니다.

## 문제 해결

**센서 여러 대를 켜면 특정 하나만 안 읽힘**
1.2.1 이전 버전의 결함입니다. MODBUS-RTU 는 프레임 사이에 3.5문자 시간(9600bps
에서 약 4ms)의 침묵을 요구하는데 그 간격을 두지 않아, 앞 센서 응답의 꼬리가
다음 센서의 응답으로 읽혀 깨졌습니다. 조회 순서상 **pH 바로 뒤에 오는 DO** 가
주로 당했습니다. 최신 버전으로 올리면 해결됩니다.

**`응답 없음`**
먼저 선에 무엇이 붙어 있는지 훑어보세요 — 한두 개만 안 읽힐 때는 대개 슬레이브 ID 문제입니다.

```bash
sudo -u shrimp365 python3 /opt/shrimp365/shrimp365_sensor.py \
  --config /etc/shrimp365/config.ini --scan
```

응답하는 ID 와 각 자리에 붙은 센서 종류를 보여 주고, 설정과 어긋난 곳을 짚어 줍니다.
아무것도 안 나오면 전원(9~24V)이나 배선 문제입니다 —
A와 B를 서로 바꿔 꽂는 실수가 가장 흔합니다.

**`CRC 불일치`**
선이 길거나 노이즈가 있습니다. 종단저항 120Ω을 달고, 전원선과 통신선을 떨어뜨려 배선하세요.

**`다른 기기가 응답함`**
같은 선에 슬레이브 ID가 같은 센서가 둘 있습니다. **한 대만 연결한 상태에서** 바꿔 주세요.

```bash
sudo -u shrimp365 python3 /opt/shrimp365/shrimp365_sensor.py \
  --config /etc/shrimp365/config.ini --set-id 1 3
#                                             ↑ 지금  ↑ 바꿀
```

프로토콜 문서의 `01 06 00 1E 00 03`(주소 레지스터 0x001E 쓰기)과 같은 동작입니다.
이미 쓰이는 번호로는 바꾸지 못하게 막아 두었습니다. 바꾼 뒤 설정 파일도 함께 고치고,
센서 전원을 껐다 켜세요 — 다시 넣어야 적용되는 제품이 있습니다.

**`HTTP 401`**
기기 키가 틀렸거나 기기가 비활성 상태입니다. 화면에서 활성 여부를 확인하세요.

**`HTTP 429`**
너무 자주 보내고 있습니다. 서버는 기기당 분당 60회로 제한합니다. `interval_seconds`를 늘리세요.

**LCD에 아무것도 안 나옴**
`sudo i2cdetect -y 1` 로 주소가 보이는지 확인하세요. 아무것도 없으면 배선(SDA/SCL)이나
I2C 활성화를 다시 보세요. 주소는 보이는데 화면이 빈칸이면 백팩 뒷면의 가변저항(대비)을
돌려 주세요. 권한 문제면 `sudo usermod -aG i2c shrimp365` 후 재시작합니다.

**보관 건수가 계속 늘어남**
서버로 전송이 안 되고 있습니다. `journalctl -u shrimp365-sensor -f` 로 사유를 보세요.
`HTTP 401` 이면 기기 키 문제, 연결 실패면 회선 문제입니다. 값은 그동안에도 계속 쌓이므로
회선이 돌아오면 자동으로 채워집니다.

**터치스크린에 `This site can't be reached`**
상태 페이지가 꺼져 있습니다. `sudo ./setup-kiosk.sh` 를 다시 실행하면 켜 줍니다.
직접 고치려면 `[webui] enabled = true` 로 바꾸고 `sudo systemctl restart shrimp365-sensor`.
수집기는 그동안에도 정상적으로 측정·전송하므로 데이터가 비지는 않습니다.

**터치스크린이 검은 화면**
`systemctl status shrimp365-sensor` 로 수집기가 도는지, 설정의 `[webui] enabled = true`
인지 확인하세요. 파이에서 `curl http://127.0.0.1:8080` 이 응답하면 수집기는 정상이고
크로미움 쪽 문제입니다. `/usr/local/bin/shrimp365-kiosk` 를 직접 실행해 오류를 보세요.

**로그의 한글이 깨짐 (`?????` `□□□`)**
고칠 곳은 파이가 아니라 접속하는 PC 쪽입니다. Windows 명령 프롬프트는 `chcp 65001`
후 접속하거나, **Windows Terminal** 을 쓰면 설정 없이 그대로 나옵니다.
파이에 모니터를 직접 붙인 콘솔 화면에서는 한글이 원리상 표시되지 않습니다 —
[INSTALL.md 부록 E](INSTALL.md#e-한글이-깨져-보일-때) 에 경우별로 정리해 두었습니다.

**터치스크린 글자가 네모(□□□)로 나옴**
한글 글꼴이 없습니다. `sudo apt install -y fonts-nanum` 후 재부팅하세요.
`setup-kiosk.sh` 가 함께 설치하지만, 그 전에 만든 장비라면 위 명령으로 채워 넣으시면 됩니다.

**값이 이상함**
센서 교정이 필요합니다. 교정 절차는 제조사 문서를 따르세요.
pH는 6.86(또는 7.00) 중간점을 **먼저** 잡고 4.01, 9.18 순으로 진행합니다.

## 서버에 저장되는 값

수질 기록으로 저장되는 항목은 **수온·pH·DO·염도** 네 가지입니다.
전도도·TDS·ORP·DO 포화도도 함께 전송되며, 기기 카드의 **마지막 수신값**에 표시됩니다.
