4. 이번 과제에서 집중한 것 — 증빙으로서의 정직성

심사·검증 대응에서 차별점이 되는 부분이다. 기능 목록이 아니라 "이 숫자를 믿어도 되는가" 에 답하는 설계다.

4-1. 산출 불가는 0 이 아니라 null 로 남기고, 왜인지 말한다

지표를 못 내면 0 으로 치환하지 않는다. 0 은 "아주 좋음" 으로 읽혀 거짓 증빙이 된다. 대신 지표마다 다른 사유와 할 일을 화면이 적는다 — 어느 입력이 비었는지, 어느 화면에 가서 무엇을 넣으면 채워지는지까지.

4-2. 지표를 켜는 입력을 전부 제품 안으로 들였다

증빙 플랫폼인데 핵심 분모·조건을 사람이 SQL 로 넣어야 하는 자리가 네 곳 있었다. 전부 메웠고, 새 SQL 없이 동작한다.

4-3. 잘못 넣은 생산량은 지우지 않고 무효로 표시한다 11/05

삭제하면 이미 발행된 리포트가 참조한 근거가 흔적 없이 사라진다. 그래서 행은 남기고 KPI 산입에서만 빼며, 누가 언제 왜 뺐는지가 감사 로그에 남는다. 되돌릴 수 있다. 사유는 필수다 — 사유 없이 빠진 생산량은 분모를 임의로 줄여 EI 를 좋게 만든 것과 구분되지 않는다. 무효 처리된 줄은 화면에서 감추지 않는다.

4-4. 생산량의 산정 근거를 함께 받는다

실측 출하·계측량인지, 입식수 × 평균체중으로 계산한 값인지, 어림인지를 필수로 적게 한다. 계산·어림이면 무엇으로 계산했는지 근거 메모를 요구한다. 생존율 보정 여부도 3상태로 받는다 — 미기재와 미적용은 다른 사실이다. 리포트가 EI 분모를 만든 두 점의 근거를 인쇄하고, 실측이 아니면 경고한다.

4-5. 전력이 실측인지 계산값인지 구분해 저장한다

계량기 실측 / 계산 / 어림을 건별로 저장하고 리포트가 밝힌다. 사람이 넣는 창구에서는 필수다. 현장 장비 수집 창구는 이 칸을 모르는 구형 장비를 위해 미기재를 허용한다.

4-6. 배출계수는 하드코딩하지 않고, 출처를 얼려서 인쇄한다

  • 2023년도 국가 전력배출계수 0.4173 tCO2eq/MWh (CO2e 기준 · 단년도 평균)
  • 출처: GIR 「2025년 승인 국가 온실가스 배출·흡수계수」 1쪽 (2025-12-17 확정 · 2025-12-18 공표), 한국에너지공단 계수표 및 공표 보도자료로 교차 확인
  • emission_factors 테이블에 append-only 로 관리. 기존 행을 고치면 과거 리포트의 근거가 사후에 바뀌므로 '수정' 이 아니라 '새 version 추가' 만 둔다
  • 리포트는 발행 시점의 계수와 출처를 얼려서 들고 있다. 출처가 빈 version 에는 「검증 대응 미비」 표시
  • CO2 단독 계수(0.4149)는 일부러 넣지 않았다 — 자동 선택이 gas_scope 를 보지 않아 CO2 단독값을 CO2e 로 집어 쓸 수 있다

4-7. Scope 2 는 location-based 와 market-based 를 나란히 보고한다 11/05

GHG Protocol 은 둘 중 하나를 고르라고 하지 않고 둘 다 보고(dual reporting)하라고 한다. REC·PPA·녹색프리미엄 증서를 등록하면 리포트 기간과 겹치는 만큼 적용되어 market-based 가 location-based 옆에 인쇄된다.

한국에는 공표된 residual mix 가 없다. 정석은 계약 전력을 뺀 잔여 전력에 residual mix 를 쓰는 것인데 그 값이 없다. 그래서 잔여분에 계통 계수를 그대로 쓰고 그 대체를 리포트가 항상 명시한다 — 과소 산정일 수 있다는 사실을 적지 않는 것이 가장 나쁘다. 계통 평균보다 높은 계약 계수는 등록 단계에서 거절한다.

이 계층은 차분검증된 산식 모듈 바깥에 있다. market-based 는 산식이 아니라 배분 규칙이고, Scope 2 산식은 다시 쓰지 않는다.

4-8. 기준선은 잠그기 전에 입력 충분성을 판정한다

잠긴 기준선은 불변이고(DB 트리거가 UPDATE/DELETE 거부) 이후 모든 전·후 비교와 Scope 2 감축량의 원점이 된다. 원본은 기간 유효성만 보고 잠갔다 — 계측값 세 건으로 계산된 기준선도 영구히 박혔다. 되돌릴 수 없는 결정에 입력 가드를 세웠다. 강행 경로는 남기되 사유 문자열을 요구하고 판정 결과 전체를 감사 로그에 남긴다.

4-9. OEI 는 「잠정 지표」로 표시하고, 기본 알림에서 뺐다 11/05

산소효율지수는 사업계획서에 산식이 없는 제안값이고, 스케일 계수와 신호등 임계값은 실증 전 가정이다. 그 사실을 값 옆에서 말한다. 아무 설정도 하지 않은 조직에서 미확정 지표로 빨간 알림이 나가지 않도록 기본 감시 목록에서 뺐다 — 알림은 "승인된 기준에 미달" 로 읽힌다. 원본 Python 과 함께 고쳐 차분검증을 유지했다(알림 128 → 104건).

4-10. 맞춤 리포트 서식은 보여 주기만 바꾼다 11/05

절·지표·표지만 정한다. 산식·배출계수·기간은 서식이 건드리지 못한다 — 서식으로 숫자가 달라질 수 있으면 "어느 서식으로 뽑았느냐" 가 감축량을 바꾸는 변수가 된다. 요약과 산식 전문은 뺄 수 없다. 발행 시점의 서식이 리포트에 얼려 들어가므로 서식을 나중에 고쳐도 옛 리포트는 그대로다. 화면과 인쇄물이 같은 판정 함수를 쓴다.

4-11. 리포트 자동 생성은 같은 기간을 두 번 만들지 않는다 11/05

주간(직전 월~일)·월간(직전 달) 일정이 마지막 기간 끝에서 이어지므로 cron 이 하루 한 번 두드려도 월요일/1일에만 새 기간이 생긴다. 같은 기간에 리포트가 둘이면 어느 쪽이 근거인지 사람이 고르게 된다. 잠긴 기준선이 없는 사이트는 실패가 아니라 "아직 조건이 안 됨" 으로 적는다. 보냈다는 사실이 증빙이다 — 수신자마다 발송 기록 한 줄(성공·실패·보내지 않음).

4-12. 비교실험(A/B)은 "무엇을 바꿔 보았는가" 를 기록으로 남긴다 11/05

대조군·처리군 두 구간을 실험이 직접 들고 있고, 결과는 조회 때마다 라이브로 산출한다(발행물이 아니다). 기준선 비교와 같은 표로 그린다. 두 구간은 겹칠 수 없고 결론은 사유가 필수다.

4-13. 쓰기 경계에서 오염을 막는다

included_quality_flags 를 빈 목록으로 두면 EI 가 0 이 되어 「감축률 100%」가 나온다. 적산 원값이 EI 분자로 새는 길도 있었다. 쓰기 경계에서 422 로 거부하고, 목록을 넓히면 경고한다.

4-14. 멀티테넌시 · 감사 · 접근성

모든 쿼리 org 스코프, RLS 정책으로 조직 격리(새 표 5개도 같은 정책). 모든 제어·설정 변경은 audit_logs 에 before/after diff 로 남는다. 신호등은 색만으로 전달하지 않고, 본문 대비 AA 4.5:1 을 토큰에서 직접 계산해 검사한다.

#결함영향

5기준선 잠금에 입력 가드 없음계측값 3건짜리 기준선이 영구히 박힘

9. 남은 것 — 기능이 아니라 한계와 전제

사양서 16화면의 기능 항목은 전부 들어갔다. 아래는 한계로 적는다.

항목내용
market-based 의 residual mix 대체한국에 공표값이 없어 잔여 전력에 계통 계수를 쓴다. 리포트가 명시하지만 값 자체는 과소 산정일 수 있다. 공표되면 계수 하나만 바꾸면 된다.
조직 전체 증서의 사이트 간 배분조직 전체 계약을 여러 사이트 리포트에 쓰면 같은 증서가 중복 계상된다. 배분표를 받지 않으므로 사람이 운영으로 막아야 한다.
증서의 월별 배분연 단위 증서를 월 리포트에 시간 비례로 자른다. 월별 배분표가 있는 계약이면 실제와 다를 수 있다.
메일 공급자 미선정기본이 log(안 보냄)다. 업체를 정해 MRV_MAIL_PROVIDER=resend 와 키를 넣기 전까지 메일은 나가지 않는다 — 그 사실은 발송 기록에 남는다.

10. 사람이 해야 하는 나머지

  • 메일 공급자 선정과 환경변수 설정 — MRV_MAIL_PROVIDER · MRV_MAIL_FROM · RESEND_API_KEY · NEXT_PUBLIC_SITE_URL
  • 배출계수 1차 대조 — 0.4173 의 원문 PDF 쪽수까지 확정하려면 한 번 더 대조
  • 외부 대시보드 0.4663 과의 값 불일치 정리 — 이 플랫폼 안에는 그 값이 없다. 함께 제출할 때 어느 쪽을 쓸지 정해야 한다(섞으면 같은 기간에 두 배출량이 나온다)
  • SNS·외부 제출물 업로드 — 저장소가 하지 않는다
