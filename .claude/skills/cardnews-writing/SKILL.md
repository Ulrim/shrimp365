# 카드뉴스 글쓰기 규칙

Shrimp365 카드뉴스는 SNS에 올리는 8장짜리 정사각형 이미지 시리즈이자, 자사 사이트 `/cardnews/<slug>`에 실려 검색 유입을 만드는 글이다. **한 번 만들면 두 곳에 쓰인다** — 카드용 짧은 문구와 사이트용 긴 본문을 함께 써야 하는 이유다.

## 독자

한국의 흰다리새우(바나메이) 양식장 운영자. 스마트폰으로 본다. 못 옆에 서 있다.
**오늘 뭘 해야 하는지** 알러 왔지, 개념을 배우러 온 게 아니다.

## 기존 발행분 — 중복 금지

작업 전에 반드시 확인한다:

```bash
ls public/cardnews/
grep -o '\$cn\$[a-z-]*\$cn\$, \$cn\$ko\$cn\$' supabase/migrations/card_news_seed_ko.sql
```

현재 한국어 7건:

| 슬러그 | 주제 |
|---|---|
| `water-quality-guide` | 수질 6항목 적정 범위 |
| `dawn-oxygen-drop` | 새벽 용존산소 급락 |
| `ahpnd-early-signs` | 급성간췌장괴사증 초기 징후 |
| `ammonia-response` | 암모니아 상승 대응 |
| `feeding-rate-calculation` | 사료 급이율 계산 |
| `mortality-diagnosis` | 폐사 원인 판별 |
| `community-board-open` | 커뮤니티 게시판 오픈 |

**같은 주제를 다시 내지 않는다.** 겹치면 각도를 바꾸거나(예: 수질 → 특정 항목 하나를 깊게) 다른 주제를 고른다.

좋은 주제: 현장에서 실제로 사고 나는 지점, 자주 틀리는 판단, 숫자로 답이 떨어지는 계산, 증상→원인 판별.
나쁜 주제: 업계 동향, 정책 소개, 회사 소식, 원론적 개념 설명.

## 8장 구성

```
01     표지    라벨 + 대제목 2줄 + 부제           [남색]
02~07  본론    한 장에 사실 하나                  [밝은 배경]
08     마무리  요약 표 + CTA + shrimp365.kr       [남색]
```

**한 장에 하나만 말한다.** 두 개를 넣고 싶으면 카드를 나누거나 하나를 버린다. 이게 가장 자주 깨지는 규칙이다.

본론 6장은 흐름이 있어야 한다. 셋 중 하나를 골라 끝까지 일관되게 간다:
- **항목 나열형** — 수질 6항목처럼 병렬 (`02 pH`, `03 DO`, …)
- **시간 흐름형** — 하루 중 산소 변화처럼 순차
- **판별형** — 증상 → 원인 → 대응

## 글자 수 — 어기면 렌더가 깨진다

| 자리 | 상한 |
|---|---|
| 표지 라벨 | 12자 |
| 표지 대제목 | 2줄, 줄당 6~8자 |
| 표지 부제 | 20자 |
| 본론 소제목 | 8자 |
| 본론 큰 값 | 8자 (숫자·범위, 등폭 렌더) |
| 본론 설명 | 22자, 한 줄 |
| 마무리 표 항목 | 라벨 8자 / 값 12자, 6행 이내 |

**긴 문장을 카드에 넣으려는 충동이 이 작업의 주적이다.** 설명하고 싶은 건 전부 `body`로 보낸다.

## 표지 훅

작동하는 형태:
- 명령 — `이 숫자만 / 외우세요`
- 반박 — `낮에 잰 DO를 / 믿지 마세요`
- 시각·수치 — `새벽 4시, / 산소가 낮습니다`

작동하지 않는 형태: "수질 관리의 모든 것", "알아두면 좋은 팁", 막연한 물음표.

## 톤

현장에서 오래 한 사람이 옆에서 알려주는 말투. 존댓말이되 딱딱하지 않게.

- 짧게 끊는다. 한 문장에 하나만
- 단정한다. "~일 수 있습니다" 대신 "~입니다". 확실하지 않으면 아예 안 쓴다
- 숫자를 준다. "적정 온도 유지"(X) → "28~32℃"(O)
- 이유를 붙인다. 숫자만 주면 안 지킨다
- 겁주지 않는다. 사고를 설명하되 공포 마케팅은 하지 않는다

쓰지 않는 표현: "요즘 핫한", "꿀팁", "필수템", 이모지 남발, 과장된 느낌표.

## 용어 — 고정어

| 뜻 | 쓴다 | 쓰지 않는다 |
|---|---|---|
| 새우를 기르는 물 공간(pond) | **양식장** | ~~못~~, ~~연못~~, ~~지(池)~~ |

**"못"은 쓰지 않는다.** 한국어에서 "못"은 부정 부사(못 한다)나 못(釘)으로 먼저 읽혀서, 특히 표지처럼 문맥 없이 한 줄만 보이는 자리에서 오독된다.
영어는 `pond`, 베트남어는 `ao`, 인도네시아어는 `tambak`을 쓴다 — 이쪽은 명사가 분명해 문제가 없다.

## DB 필드

`app/api/cardnews/route.ts`의 `normalize()`가 아래 상한을 강제한다. 넘으면 **에러가 아니라 조용히 잘린다.**

| 필드 | 상한 | 규칙 |
|---|---|---|
| `slug` | 80자 | 영문 kebab-case. `lib/card-news.ts`의 `slugify()` 규칙 |
| `locale` | — | `ko` `en` `vi` `id` 중 하나 |
| `title` | 200자 | 검색어를 앞에. `흰다리새우 수질 기준표 — 이 숫자만 외우세요` |
| `summary` | 300자 | 2~3문장, 숫자 하나 이상. 목록 카드와 OG 설명에 그대로 쓰인다 |
| `body` | 20000자 | 아래 구조 |
| `tags` | 12개 | `#` 없이 |

### body 구조

```
도입 2~3문장 — 독자가 겪는 상황에서 시작한다

■ 소제목

문단. 카드에서 못 한 이유·맥락·예외를 설명한다.

■ 소제목

…

■ 기록이 기준보다 중요합니다      ← 마지막 실무 조언

Shrimp365는 …. 무료로 사용하실 수 있습니다.   ← CTA
```

- 소제목은 `■ `로 시작한다. **마크다운 `##`을 쓰지 않는다** — 렌더러가 처리하지 않고 그대로 노출된다
- 1,500~3,000자
- 마지막 문단은 반드시 Shrimp365 CTA. 방금 설명한 문제를 서비스가 어떻게 덜어주는지로 연결한다
- `body`는 카드의 요약이 아니라 **카드에서 못 한 설명**이다

### 태그

기존 태그를 우선 재사용한다 — 사이트 내 연관 글 연결에 쓰인다.

```
수질관리  흰다리새우  용존산소  암모니아  염도  새우양식
질병관리  사료관리  폐사  아질산  수온  양식장관리
```

## 사실 확인 — 가장 중요

**이 글은 실제 양식장 운영자가 읽고 그대로 따라 한다. 수치가 틀리면 새우가 죽는다.**

- 근거 없는 수치를 쓰지 않는다. 모르면 조사하거나 비워 두고 넘긴다
- 흰다리새우(*Litopenaeus vannamei*) 기준인지 확인한다. 다른 종 수치를 섞지 않는다
- 기존 7건과 수치가 어긋나면 그대로 보고한다. 조용히 다른 숫자를 쓰지 않는다

## 다국어

기본은 한국어 1종. 확장할 때는 **같은 `slug`에 다른 `locale`**로 넣는다 — 그래야 `hreflangMap()`이 언어 간 링크를 만든다. 번역이 아니라 현지 독자에게 맞게 다시 쓰는 것이 원칙이지만, 수치는 반드시 동일해야 한다.
