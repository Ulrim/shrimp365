`run_test_eval.sh` 는 test 분할이 **이미지 445장·정답 박스 3,699개**가 아니면 측정하지 않고 멈춘다.
묶음 `vision/sta_블루스타트업/` 과 다시 나눈 `vision/datasets/` 는 `.gitignore` 로 커밋에서 빠져 있다(원본 이미지 포함).

## 1. 시험 대상 확인 (약 1분)

```bash
cd vision
set -o pipefail                                       # tee 뒤에서도 실패가 보이게 한다
git rev-parse HEAD                                    # 실행 코드의 커밋
git status --short -- .                               # 아무것도 안 나와야 한다(추적 파일 변경 없음)
sha256sum ai/models/shrimp_yolov8n_416.onnx           # ae95071c7e53df7e828e0faf51a54e0f7c5bb3010312b1d305949af12d533804
(cd sta_블루스타트업/01_시험데이터/test && sha256sum -c --quiet ../sha256sums.txt && echo "시험 데이터 일치")
cat sta_블루스타트업/01_시험데이터/통계.txt             # 445장 · 3,699개
```

- 모델 sha256 은 신청서에 적은 값과 같아야 한다.
- `sha256sum -c` 는 시험 이미지·라벨 한 파일씩 전날 고정한 목록과 견준다.

## 2. 측정 (약 1~3분)

```bash
STA="$PWD/sta_블루스타트업"
rm -f $STA/00_* $STA/02_* $STA/03_* $STA/04_* $STA/05_*    # 전날 결과를 지운다(01_시험데이터 는 그대로)
.venv/bin/python ai/trainer/eval_detect.py \
  --weights ai/models/shrimp_yolov8n_416.onnx \
  --images $STA/01_시험데이터/test/images --labels $STA/01_시험데이터/test/labels \
  --conf 0.25 --bootstrap 2000 \
  --log-dir $STA 2>&1 | tee -a $STA/05_실행로그.txt
echo "종료 코드 ${PIPESTATUS[0]}"
```

화면에서 확인할 것

- `이미지 445장 · 정답 박스 3,699개`
- `mAP@0.5`, `Precision`, `Recall`, `F1`, `계수 오차율 평균`
- 맨 아래 `판정` 두 줄(시험 항목 1·2)

시험 데이터가 고정한 목록과 한 파일이라도 다르면 **재기 전에** `[중단]` 으로 끝난다(수치가 나오지 않는다).
`[중단]` 이 나온 묶음은 보내지 않는다.

## 3. 로그만으로 다시 계산 (약 10초)

```bash
.venv/bin/python ai/trainer/recompute_detect.py --dir $STA 2>&1 | tee -a $STA/05_실행로그.txt
echo "종료 코드 ${PIPESTATUS[0]}"
```

- 모델·이미지를 읽지 않고 `02_예측별_결과.csv` 와 `02_정답별_결과.csv` 로 계산한다
  (`02_이미지별_결과.csv` 는 교차 확인과 이미지 이름 목록에만 쓴다).
- 예측과 정답의 짝짓기(IoU 매칭)는 다시 하지 않는다. 로그의 TP(0/1) 열에서 출발해 그 뒤 집계를 모두 다시 한다.
- 모든 줄이 `일치`, 마지막 줄이 「결과: 모두 일치」 여야 한다. 하나라도 다르면 종료 코드 1.

### 시험원에게 설명할 내용 — 데이터별 결과에서 최종값이 나오는 길

| 최종값 | 어느 로그에서 | 어떻게 |
|---|---|---|
| 정답 총수 N | `02_정답별_결과.csv` | 줄 수 (3,699) |
| mAP@0.5 | `02_예측별_결과.csv` | 모든 이미지의 예측을 `전체순위`(신뢰도 내림차순)로 세우고, `TP@0.50` 열로 누적 TP·FP → 정밀도·재현율 곡선 → 101점 보간 평균 |
| mAP@0.5:0.95 | 같은 파일 | `TP@0.50` … `TP@0.95` 열 10개로 같은 계산을 해 평균 |
| Precision·Recall·F1 | 두 파일 | TP = 정답별 로그에서 `운영임계값에서_탐지`=1 인 줄 수, FP = 예측별 로그에서 `운영임계값_이상`=1 인 줄 수 − TP, FN = N − TP |
| 계수 오차율 | 두 파일 | 이미지마다 검출 수(`운영임계값_이상`=1 인 예측 수)와 정답 수(정답 줄 수)로 \|검출−정답\|÷정답 → 평균·중앙값·최대·±20% 이내 비율 |

**mAP@0.5 는 이미지별 AP 의 평균이 아니다.** `02_이미지별_결과.csv` 의 `AP@0.5(이미지 단독)` 은 참고값이고
(정답 0마리 이미지는 빈칸), 최종값은 예측별 로그로 계산한다. 식은 `recompute_detect.py` 머리말에 번호를 붙여 적어 두었다.


## 예상 소요시간

| 단계 | 시간 |
|---|---|
| 1. 시험 대상 확인 | 약 1분 |
| 2. 측정 — 445장 CPU 추론(장당 수십 ms) + 부트스트랩 2,000회 + sha256·로그 쓰기 | 약 1~3분 |
| 3. 재계산 | 약 10초 |
| 4. 압축 | 약 1분 |
| 설명·질의 포함 전체 | **30분 이내** |

> 2단계 시간은 수조 사진 12장을 잰 값(장당 40~55 ms, x86 CPU)에서 어림한 것이다.
> 사전 측정을 마치면 `03_최종결과.json` 의 `추론시간_ms` 와 실제 걸린 시간을 이 표에 적어 넣는다.

## 판정 기준은 설정값이다

기본값은 시험신청서 초안과 같다. 바꿀 때는 `eval_detect.py` 인자로 준다(`run_test_eval.sh` 에서는 `EVAL_ARGS="…"`).

| 인자 | 기본값 | 뜻 |
|---|---|---|
| `--pass-map50` | 0.75 | mAP@0.5 가 이 값 이상이면 적합 |
| `--count-judge` | `mean` | 계수 오차율 판정 방식: `mean`(이미지별 오차율 평균) · `within`(±20% 이내 비율) · `both` |
| `--pass-count-mean` | 0.20 | 평균 오차율이 이 값 이하면 적합 |
| `--pass-count-within` | 없음 | ±20% 이내 비율이 이 값 이상이면 적합(`within`·`both` 일 때 반드시 지정) |
| `--count-tolerance` | 0.20 | 「이내」로 볼 허용오차 |

판정은 `03_최종결과.json` 에 적힌 값(소수 넷째 자리 반올림)을 기준과 견준다.
측정값은 판정 기준과 무관하게 모두 기록된다. 기준에 못 미쳐도 임계값(`--conf`)·설정을 바꾸지 않는다.

## 시험 PC 조건

명령은 **bash + GNU `sha256sum`** 기준이다(Linux, 또는 Windows 의 WSL). macOS 는 `sha256sum` 대신
`shasum -a 256` 을 쓴다. `run_test_eval.sh --rerun` 은 `sha256sum` 이 없으면 그 대조를 건너뛰지만,
`eval_detect.py` 가 같은 대조를 스스로 한 번 더 하므로 고정 여부는 어느 쪽에서든 확인된다.

## 막혔을 때

| 증상 | 뜻 · 할 일 |
|---|---|
| `[중단] 시험 데이터가 고정된 목록과 다릅니다` | 시험 이미지·라벨이 전날과 다르다. 폴더를 건드렸는지 확인. 측정하지 않는다. |
| `[중단] 학습 기록의 test 분할 … 과 다릅니다` | 원본 데이터셋 판이 다르다. 드라이브의 `shrimp_cf.v1i.yolov8`·`Counting PL.v1i.yolov8` 인지 확인. |
| `--log-dir 는 조각 추론(--tile)과 함께 쓸 수 없습니다` | 시험은 조각 추론 없이 한다. `--tile` 을 뺀다. |
| 재계산이 `불일치` | 로그 파일이 측정 뒤에 바뀌었거나 열렸다 저장됐다(엑셀로 열어 저장하면 바뀐다). 2단계부터 다시. |
| `00_시험대상_해시.txt` 에 `추적 파일 변경 있음 ⚠` | 커밋되지 않은 코드 수정이 있다. `git status` 로 확인하고 되돌린 뒤 다시. |
